# X35c — sources for each decision

Change: X35c, the Facebook Page fan-out service (`post/fanout.go`, `cmd/fanout`, port 8090). The donor shares an active listing: Muse Spark 1.3 writes a short public post from the photo, the title and the servings; the Pages API posts it with the photo to the Icarus Page; a claim (the listings service calls `/v1/fanout/status`) or the timer edits the post to start with `[CLAIMED]` or `[EXPIRED]`. Build only: no compose or Caddy route, no Page token yet. Decisions by T9, 2026-10-28: "we use muse to craft the emails or messages", "for facebook lets just post", "we can limit the regular fan out for items to facebook only". Read 2026-10-28.

Own evidence: 8 Go tests (a fake Graph API: the photo post and its fields, one post per listing (also with 4 taps at the same time), the claim edit once, its own token, the text rules and the check, the sweep, the store). No live call yet.

### D82. Facebook Page posts, not Groups
- https://developers.facebook.com/blog/post/2024/01/23/introducing-facebook-graph-and-marketing-api-v19/ — the Groups API (`publish_to_groups`) was deprecated in v19 and removed from all versions after 90 days.
- https://developers.facebook.com/documentation/pages-api/getting-started — a Page access token with `pages_manage_posts`; `POST /{page_id}/feed`.

### D83. One photo post; the claim edits its message
- https://developers.facebook.com/docs/pages-api/posts — `POST /{page_id}/photos` publishes a photo (the answer has `id` and `post_id`); `POST /{page_post_id}` with `message` updates a post.
- https://developers.facebook.com/docs/graph-api/reference/page/photos — the photo is a multipart file (historically named `source`); `caption` is the text (`message` is deprecated there); needs a Page token with `pages_manage_posts`, `pages_read_engagement`, `pages_show_list`; the answer has `id` (photo) and `post_id`.

### D84. The public post has no pickup text, no link from the model, no safety claim
- https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/data-minimisation/ — data minimisation: "adequate, relevant and limited to what is necessary"; a public post needs the food, not the donor's address.
- https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/ — "apply proper input validation on responses coming from the model": a link or the pickup text in the text stops the post, and a second Muse Spark call must answer `ok: true` before it goes public.
- https://guptadeepak.com/agent-security/threats/llm01/ — prompt injection: the title is user text, so it goes to the model as a JSON value marked as data.

### D85. The claim comes from the listings service with its own token; the sweep is off until that hook exists
- https://owasp.org/API-Security/editions/2023/en/0xa2-broken-authentication/ — the analyze token is in the app bundle (public), so the status route has its own internal token and no public route.
- https://www.rfc-editor.org/rfc/rfc9110#name-idempotent-methods — the same status sent again changes nothing; a claimed post stays claimed.
