# X48n — sources for each decision

Change: X48n (UI), the voice clip can be stopped on iOS (`mobile/src/webvoice.ts`, `mobile/tests/webvoice.test.mts`, `mobile/package.json`; NEW_WORK.md 61). T9 (2026-10-30): "there is an issue with ios for the voice update functionality, user is able to press the button to start voice recording but not stop it. on computer browser, and andriod this is not the case and works just fine."

Own evidence (code reading and cloud tests, 2026-10-30): `startWebCapture` made the AudioContext after `await getUserMedia` and then waited `await ctx.resume()` with no limit. `ClipSession.stop()` during "starting" waits for the start (`mobile/src/clipsession.ts`), so when the start does not end, Stop does nothing. Cloud tests with a fake iOS context (a resume asked for outside the tap never ends): before this change the start would wait forever; now the context is made and resumed before the microphone prompt, and a start whose audio cannot run fails within the limit and closes the microphone. Not measured on an iPhone here (no WebKit in the cloud): T9 checks it on the phone.

### D225. The AudioContext is made and resumed in the tap, before the microphone prompt; the wait has a limit
- https://www.mattmontag.com/web/unlock-web-audio-in-safari-for-ios-and-macos — "user interaction is required to unlock the AudioContext"; the browser message: the context "must be resumed (or created) after a user gesture on the page".
- https://bugnet.io/blog/how-to-fix-web-game-audio-context-stuck-suspended-on-mobile — the same failure on mobile browsers: the context stays suspended when it is made outside a gesture.
- The wait for "running" now has a 2 s limit (`RESUME_WAIT_MS`): a start that cannot run fails with "Tap the microphone again" and closes the microphone, so the button never stays stuck.
