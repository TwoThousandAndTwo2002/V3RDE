### D231. The voice route also takes typed text: no transcription, the same Muse Spark mapping
- https://dev.meta.ai/docs/speech-to-text — Muse Voice Transcribe turns the clip into text; a typed line is already text, so that call (and its cost) is left out.
- https://github.com/meta-models/meta-model-cookbook — the Muse Spark JSON call that maps the text to changes; the same prompt, rules and limits for both kinds of line (`ApplyRules`).
- The app takes at most 500 characters; the service takes at most 2000 bytes (`VoiceMaxText`: 500 characters of 4 bytes) and cleans the line with `cleanText`, as a transcript; a line of control characters only is refused. The answer and the ledger say `source` voice or text.

### D232. The changes go into the list at once, with Undo on the last change only
- https://www.csfieldguide.org.nz/en/chapters/human-computer-interaction/usability-heuristics/ — "user control and freedom": a clearly marked way out (undo) instead of a confirmation step.
- T9's decisions on the mockup (quoted above). Undo shows only while the list is as the last change left it (a later hand edit ends it), so Undo never removes the user's own edits.
- Independent review: the answer goes onto the list as it is when the answer comes (a hand edit while the line is out stays); one line at a time; a line may not remove every item (the review needs one; Start over does that); Post waits while the microphone is on.
