### D298. The claim link is /l/<listing_id>; the app reads it once and opens Receive
- https://developer.mozilla.org/docs/Web/API/History/replaceState — "The replaceState() method of the History interface modifies the current history entry"; the app puts `/` back (as it does for the reset link), so a reload does not skip the role sheet again.
- Only an id of the listings form (`l_` and 16 hex characters) counts; a query after it is allowed (Meta adds a `fbclid` query parameter to the URL of a link that is clicked: https://developers.facebook.com/docs/marketing-api/conversions-api/parameters/fbp-and-fbc — "ClickID is a Meta-generated parameter that is passed with the URL", example `https://example.com/?fbclid=…`); any other path is not a claim link (test).
- The app scheme `v3rde://l/<listing_id>` works the same on a phone, at start and while the app runs (React Native `Linking`: https://archive.reactnative.dev/docs/linking — `getInitialURL()`: "If the app launch was triggered by an app link, it will give the link url"; `addEventListener` with the `url` event for links while the app runs).
