### D183. Read the list where the live answer has it
- https://feedam.org/developer-portal — the public read endpoints need no key; `GET /api/resources/search` takes `zip` and `mode`; 10K requests a day per IP.
- The answer's list is `resources`. The service now reads it first (and still reads the other names). The street is in `address`, and the city, state and zip are their own fields, so the address the app shows is built from all four. The type is `resource_type` with underscores (`food_bank`), so the food-bank rule accepts `food bank`, `food_bank` and `foodbank`.

### D184. Each place says where its record comes from
- https://feedam.org/AGENTS.md — the content is under CC BY 4.0; citations name Feed America (feedam.org).
- The live answer's own attribution says that each record comes from the source named in its `data_source` field (for 80219: `plentiful_org`, `ampleharvest_org`), and its `license` field is empty. So each place now has `source`, and the app can show it next to the Feed America attribution. Whether the demo may show these records is a rights question for T9 (plan F3), not a code decision.

### D185. The reason of a directory failure is logged
- https://sre.google/sre-book/monitoring-distributed-systems/ — record why a request failed, so the cause can be found without a new test.
- The first live failure gave only "the directory is unavailable" and needed a separate check to find the cause. The donor still gets the short 502; the events line now has `detail.directory_error` (the parser's or the HTTP client's error, at most 300 bytes) and `directory_ms`.
