# X35e — sources for each decision

Change: X35e, the voice clip is made on the device (the edge), as the WAV the voice service takes: 16 kHz, mono, 16-bit PCM, exact header sizes. `mobile/src/wav.ts` (pure: resample, 16-bit, the WAV header), `mobile/src/webvoice.ts` (web capture), `mobile/src/voicerec.ts` (the recorder hook for every platform), `mobile/public/voice-capture-worklet.js`, `api.voice()`, the `expo-audio` dependency and its plugin. No UI yet: the mic button comes with its own mockup (style guide rule). Decisions by T9, 2026-10-28: "the wav recording review and honestly this should be done at edge"; "ensuring that you are not going by memory to make a change but rather pulling code and making changes based on context from direct sources". Read 2026-10-28, in the installed code where it says more than the docs.

Own evidence (scripts, not estimates):
- Chromium (Playwright) with a fake microphone that plays a 440 Hz tone (48 kHz WAV): the real `src/webvoice.ts` (bundled alone with esbuild) recorded 2.5 s; the browser gave 44,100 Hz; the clip came out 16,000 Hz, mono, 16-bit, 39,984 frames, pitch from zero crossings 439.8 Hz; no page error. The "no getUserMedia" path gave the error code `unsupported`.
- The server's own `NormalizeWAV` (post/wav.go) took that clip byte for byte (`converted: false`).
- `expo export -p web` ships `voice-capture-worklet.js` unchanged; Caddy's catch-all `file_server` serves it.
- `expo config --type introspect`: iOS `NSMicrophoneUsageDescription` set, no `UIBackgroundModes`; Android `RECORD_AUDIO` + `MODIFY_AUDIO_SETTINGS`.
- tsc against the installed expo-audio 58.0.10 types; mobile tests 28 -> 31.

### D95. The clip is made on the device in the one format the endpoint takes
- https://dev.meta.ai/docs/speech-to-text — the batch endpoint accepts "a RIFF/WAVE container with mono, 16-bit integer PCM at 16 kHz or 24 kHz"; the device sends 16 kHz with exact sizes, so the server sends it on unchanged (post/wav.go pass-through).

### D96. Android and iOS: expo-audio 58.0.10 useAudioStream, written as WAV by Expo's own writer
- https://docs.expo.dev/versions/latest/sdk/audio/ — `useAudioStream` (raw PCM, `sampleRate`, `channels`, `encoding: 'int16'`); `startFileRecordingAsync({format: 'wav'})` / `stopFileRecordingAsync()` give the file `uri`, `duration`, `sampleRate`; "the actual rate may differ if the hardware cannot deliver it".
- https://registry.npmjs.org/expo-audio — version 58.0.10, MIT; it is the version `expo` 58.0.19 pins (`bundledNativeModules.json`: `"expo-audio": "~58.0.10"`). Its code: iOS converts to the asked rate (`AVAudioConverter`, ios/AudioStream.swift); Android's `AudioRecord` falls back to a rate the device supports (android/.../AudioStream.kt); the WAV header is kept valid while it records (AudioStreamFileWriter).

### D97. Web: our own capture, because expo-audio's web stream is a stub
- https://registry.npmjs.org/expo-audio — in 58.0.10, `build/AudioStream.web.js` is `return { stream: null, isStreaming: false }`, although the docs list Web.
- https://developer.mozilla.org/en-US/docs/Web/API/navigator/mediaDevices.getUserMedia — `getUserMedia` "can only be used in secure contexts" (https); `NotAllowedError` when the user denies (shown as "Allow the microphone").
- https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode/port — `audioWorklet.addModule(url)`, `registerProcessor`, and `port.postMessage` from the processor to the page: the worklet posts each 128-frame block.

### D98. Capture at the device rate and resample on the device
- https://caniuse.com/mdn-api_audiocontext_audiocontext_options_samplerate_parameter — the `AudioContext` `sampleRate` option is listed for Chrome 74, Firefox 61, Safari 14.1, iOS Safari 14.5, and Chrome for Android only from 156; so the context runs at the device rate (44,100 Hz in the Chromium test) and `src/wav.ts` resamples with the server's rule (post/wav.go: a moving average over the ratio, then linear interpolation).

### D99. The plugins: one microphone text, no background audio
- https://docs.expo.dev/versions/latest/sdk/audio/ — the `expo-audio` config plugin (`microphonePermission`, `recordAudioAndroid`, `enableBackgroundRecording`, `enableBackgroundPlayback`); its code (plugin/build/withAudio.js) adds the iOS `audio` background mode when `enableBackgroundPlayback` is not set (default true), so both are set to false.
- https://github.com/expo/expo/discussions/24034 — a WAV recording module "added a background audio mode to Info.plist, which drew an App Store review question"; and `expo-camera` was set with `microphonePermission: false`, which can remove the iOS text, so both plugins carry the same text.

### D100. The server keeps its fallback for an Android device that refuses 16 kHz
- https://docs.expo.dev/versions/latest/sdk/audio/ — the delivered rate "may differ from the requested rate"; the clip reports its real rate, and the server's strict reader converts such a clip (X35d, D88). Every other clip is sent byte for byte.
