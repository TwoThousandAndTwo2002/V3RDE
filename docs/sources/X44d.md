### D176. Only the ledger, and only what was measured
- https://en.wikipedia.org/wiki/Percentile — the nearest-rank method: the P-th percentile is "the smallest value in the list such that at least P percent of the data is less than or equal to that value." No value is made up between two measured ones.
- The plan says the numbers come from the ledger and the sidecars. The report reads only `ledger-YYYYMMDD.jsonl` and `samples-YYYYMMDD.jsonl` (the merged sidecar spools). Edge: the gate's own `total_ms` and `invoke_ms`, the barcode service's `total_ms`, and the memory (`rss_mib`) of both services from the samples. Cloud: the `ms` of each Meta call (`calls[]`, 2xx only): SAM 3.1 (`sam:*`), Muse Spark (`muse:*`, `touchup:check`, `voice:map`, `rescue:draft`), Muse Image (`touchup:edit`), Muse Voice Transcribe (`voice:transcribe`). Scan: `total_ms` of a 200 scan by source, and the cost of a vision scan. Each row names the ledger field it comes from, and `n`, so the video shows where each number is from.

### D177. A third binary in the telemetry image, no new service
- https://docs.docker.com/reference/cli/docker/container/run/#entrypoint — `--entrypoint` runs another binary of the same image.
- The report is a command, not a server: `docker run --rm --entrypoint /edgecloud -v <ledger>:/ledger-data:ro v3rde-telemetry` on the box (the ledger folder read-only). No compose service, no port, no route. The image is built only when the telemetry code changes (D151), and this change is the only one in the chain that changes it.
