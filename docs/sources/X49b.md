### D241. One round: the app text from the deployed tree, the graph diff, a tag, only the changed and reached texts, batch + loop, publish
- LIF entries 56 (the text graph), 64 (one screen in one call), 65 and the LIF handoff section 6 (batch + loop: the fewest flags, 167, with 414 calls for 5 languages).
- https://docs.docker.com/compose/how-tos/profiles/ — a service with a profile is not started by `up`; `docker compose --profile lif run --rm lif` runs it once and removes it, so the 10 GB of MetricX are held only during a round.
- The tag is `r<UTC time>`; `rounds/<tag>.json` keeps what changed and why; `review/<tag>.json` keeps the texts that failed two times, with the judges' reasons. The published files are written to a temp file, then renamed (an app never reads half a file).

### D242. MetricX scores in the same container, no Docker inside it
- https://docs.docker.com/engine/security/#docker-daemon-attack-surface — a container with the Docker socket controls the host: the round image has MetricX (the qe/Dockerfile lines, the same pins) and runs `run_predict.py` itself (`-qe local`), with the same arguments as `qe/score.sh`.
- Scores are recorded and do not decide pass or fail (LIF handoff, section 6, item 2: MetricX does not separate the ways and sometimes prefers the wrong form). So a scorer failure (for example MetricX stopped at the memory limit) leaves the tries unscored and the round goes on (independent review: before, it lost the whole round after the model calls were paid).
- Independent review: a language that failed is tried again on the next deploy even when the app text did not change (`round.json` keeps the failed languages); a text that went to a person is not tried again (T9: after two tries, a person decides); a first round that stopped early keeps the work of its languages.

### D243. The edge serves the translations at /i18n/, checked again on each use
- https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Cache-Control — `no-cache`: a browser may keep a copy but asks the server first, so a new round shows at once.

### D244. The round needs 10.6 GB free memory and a key file, else it is skipped; it never fails a deploy
- https://huggingface.co/google/metricx-24-hybrid-large-v2p6 — the scorer model (1.2B parameters); LIF L1 D6: in fp32 it needs a 10 GB limit. The box (t4g.xlarge, 16 GB) uses about 1 GB for the stack (the X40c deploy log: 1059 MB used).
- https://docs.docker.com/engine/storage/bind-mounts/ — a missing key file would be mounted as an empty folder (Docker makes a missing bind source), so the script checks the files first. Exit 0 on a translation failure: the live files stay as they were.
