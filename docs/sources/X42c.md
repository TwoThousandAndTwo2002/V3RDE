Own evidence (2026-10-29): X42b read Caddy's access log for that request: `Content-Type: application/x-www-form-urlencoded`, `Content-Length: 0`, no `Transfer-Encoding`. curl sent no Content-Type, so the header was added on the public path. The app's calls take the same path. New test: a Content-Type with an empty body (form, JSON) and an empty body with no length start the job (202); a body of one byte with no length (chunked) is still refused. Mutations caught: the old Content-Type rule, and a check that never reads a chunked body.

### D159. Refuse a real body, not a Content-Type
- https://pkg.go.dev/net/http#Request — "ContentLength records the length of the associated content. The value -1 indicates that the length is unknown. Values >= 0 indicate that the given number of bytes may be read from Body." (the same text is in `go doc net/http.Request`, Go 1.24.7).
- The rule exists so that no photo is uploaded to the touch-up (only `photo_id`, X36a). A request is refused when it has a known length over 0, or a body of unknown length that is not empty; a Content-Type alone is not a body.

### D160. A test stops its event writer before its folder is removed
- https://pkg.go.dev/testing#T.Cleanup — "Cleanup registers a function to be called when the test (or subtest) and all its subtests complete. Cleanup functions will be called in last added, first called order." (the same text is in `go doc testing.T.Cleanup`, Go 1.24.7).
- The cloud preflight of this change failed one time: `TestFailsClosed` gave "TempDir RemoveAll cleanup: ... directory not empty" (1 time in 15 runs), because the gate's event writer could still make the day's file while the test's folder was removed. Each test recorder is now closed by a Cleanup that is added after its TempDir, so it runs first; `Recorder.Close` can now be called two times. 40 runs after the fix: no failure; also with `-race` and with the LiteRT and libjpeg-turbo tags (29).
