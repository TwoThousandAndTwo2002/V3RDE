### D208. The edit is code: crop, Catmull-Rom resize, levels, grey-world white balance, exposure, saturation, unsharp mask
- https://avisynthplus.readthedocs.io/en/latest/avisynthdoc/corefilters/resize.html — b = 0, c = 0.5 "is the Catmull-Rom spline and a good suggestion for sharpness"; above c = 0.6 the filter rings. The kernel is widened when it shrinks (no aliasing); it enlarges at most 2x ("make it bigger" without inventing detail).
- https://docs.opencv.org/4.12.0/javadoc/org/opencv/xphoto/GrayworldWB.html — "scales the values of pixels based on a gray-world assumption", with a threshold so that only some pixels count. Here only the mid-tones (luminance 0.1 to 0.9) count, and the gains stay in 0.8 to 1.25.
- https://scikit-image.org/docs/0.25.x/auto_examples/filters/plot_unsharp_mask.html — "enhanced image = original + amount * (original - blurred)"; the radius is the sigma of the Gaussian. The sigma here grows with the size of the image (1 px per 1,000 px of the long edge, at least 0.8).
- Code only means no pixel is painted: the food stays the real food, so this mode needs no check call, and it costs nothing. Go, in parallel over the rows (T9's rule: "Use Go as much as possible").

### D209. The hybrid: Muse Spark chooses the numbers; Muse Image only paints the background; SAM keeps the real food
- https://dev.meta.ai/docs/image-understanding — Muse Spark reads an image and answers JSON; the answer here is numbers only (`LookPrompt`), clamped by `LookFrom`, so the model cannot make the code change the food.
- https://dev.meta.ai/docs/sam/segmenting and https://dev.meta.ai/docs/sam/reading-segmentation — one concept per request ("food"); each instance has a box and a box-local mask (`MaskRaster` puts it on the edited photo).
- https://developer.meta.com/ai/resources/blog/build-with-muse-Image/ — Muse Image `POST /v1/images/edits`, $0.01 per image. Only the background of this edit is used: the food pixels come from the code edit through the mask (`analyze.Composite`, a soft edge of 1/250 of the long edge), so a change to the food in the edit does not reach the post.
- SAM and the background edit run at the same time (T9: "make this as parallel as possible"). The tool runs 2 photos at a time (`-parallel 2`): the independent review counted about 110 MB of float planes for one 2376 px photo, and the box has 1.9 GiB; the resize keeps one middle plane at a time.
