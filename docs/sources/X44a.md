### D165. A cap for each caller, as well as for each service
- https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/ — "Configure spending limits for all service providers/API integrations."
- The audit list (S1, fact 3): "The daily caps are for each service, not for each caller ... When one caller uses all of a cap, that feature stops for all callers, app users too." The service cap stays (it limits what we pay); the new cap limits what one caller can use. The caller key is the key the rate limit already uses (`Caller.RateKey`: `u:<user id>` or `ip:<address>` in the post services; `user:<id>` or the address in analyze), so the two limits name a caller the same way.
- Until the SME's `X-Client-Ip` setting is in (audit item 3), every bearer caller through API Gateway has one address, so the bearer callers share one key. They can then use only their share, and the app's users keep theirs.

### D166. Over the caller's own share: 429, not 503
- https://datatracker.ietf.org/doc/html/rfc6585 — section 4: "The 429 status code indicates that the user has sent too many requests in a given amount of time ("rate limiting")."
- The service cap stays `503 daily_cap_reached` (the feature is off for everyone). A caller over its own share gets `429 caller_daily_cap_reached`, so the app can tell the user that the limit is theirs, and the other users are not affected.

### D167. The share survives a restart: cap_key on every line
- https://pkg.go.dev/encoding/json#Unmarshal — a line without the new field decodes with the field empty, so the lines written before this change still add to the total.
- The budget already starts from the events file of the day (`SpentOn`, fsync on every line). Each line now has `cap_key`, and the touch-up job line takes the key of the caller who started the job, so a restart restores each caller's spend as well as the total.
- Values in compose (env, so they change without a code change): analyze $5 of $20, touch-up $0.50 of $2, voice, rescue and fan-out $0.25 of $1 each: at least four callers must use their whole share before a feature stops for everyone. `-caller-cap-usd 0` turns the caller cap off.

### D168. How hard the ids are to guess (audit item 4)
- https://pkg.go.dev/crypto/rand — "Package rand implements a cryptographically secure random number generator."
- Read in the code: `photo_id` (`inference/photos.go newPhotoID`) and `touchup_id` and the edited photo's id (`post/touchup.go newHex(16)`) are 16 bytes from `crypto/rand`, shown as 32 hex characters: 128 random bits each. A wrong id gets the same 404 as a photo of another owner, so an id cannot be probed (OWASP API1:2023). No change is needed for this item.
