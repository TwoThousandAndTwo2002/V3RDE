# U6 — sources for each decision

Change: U6 (branch `ui`), the field parts of V3RDE: the focus border, the Show/Hide button, the text link, the busy and hover pill, and their colour tokens.

### D1. A reference to measure: the earlier sign-in screen

No sign-in mockup was approved after the kickoff. T9 chose (Oct 29) to render the earlier sign-in screen (Icarus `457a62c`, from before the kickoff) in a harness and use the shots only as a reference to measure, the same way as the X25 scan mockup. Playwright typed and tapped through 9 states (empty, focus, filled, show, short, offer, busy, failed, hover) on a phone (390 × 844 at 3×) and a desktop (1440 × 900 at 2×); the script answered the sign-in requests. No code of the earlier screen is in V3RDE.

- Playwright, Page.route (answer requests in a test): https://playwright.dev/docs/api/class-page#page-route
- Playwright, browser contexts (viewport, deviceScaleFactor, colorScheme): https://playwright.dev/docs/api/class-browser#browser-new-context

### D2. The focus border, and no browser focus ring

The reference field shows a 2 pt border in `accent` while it has the focus. On the web, the browser draws its own focus ring (`outline-style: auto`), which does not use the outline width; the field sets `outline-style: none` on the web only (React Native has no "none" outline style; react-native-web passes the style to the DOM) and draws its own border, so the focus stays visible.

- MDN, outline-style: https://developer.mozilla.org/en-US/docs/Web/CSS/outline-style
- WCAG 2.1, focus visible: https://www.w3.org/WAI/WCAG21/Understanding/focus-visible.html
- React Native, View style props (outline): https://reactnative.dev/docs/view-style-props

### D3. Show/Hide: a text button inside the field, 44 pt

The text sits where it sits in the reference (76 pt of field padding on the right). Its touch area is 44 pt high (the reference had 40 pt; T9 accepted 44, Oct 29), and it has its own name for a screen reader ("Show password").

- Apple HIG, accessibility (44 × 44 pt): https://developer.apple.com/design/human-interface-guidelines/accessibility
- WAI-ARIA APG, button pattern (name): https://www.w3.org/WAI/ARIA/apg/patterns/button/

### D4. The label is the name of the input

The visible label of a field is also its `aria-label`, so a screen reader names the email and the password fields (the reference password field had no name).

- React Native, accessibility (aria-label): https://reactnative.dev/docs/accessibility#aria-label
- WCAG 2.1, labels or instructions: https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html

### D5. TextLink: an action in a line of text

"Create one" starts an action (it signs up), so it is read as a button, not as a link, and it is in the Tab order.

- WAI-ARIA APG, link pattern (a link goes to a resource; a button does an action): https://www.w3.org/WAI/ARIA/apg/patterns/link/

### D6. The busy pill keeps the focus; hover feedback

A disabled pill loses the keyboard focus on the web (the focus goes to the page). The busy pill is not disabled: a tap does nothing, `aria-busy` tells a screen reader that it waits, and the focus stays. With the mouse on a pill (web), its opacity is 0.92, as on the reference (react-native-web gives the Pressable style a `hovered` state).

- MDN, aria-busy: https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-busy
- react-native-web, Pressable (hovered, aria-disabled from disabled): https://github.com/necolas/react-native-web/blob/0.21.1/packages/react-native-web/src/exports/Pressable/index.js

### D7. Colours (T9, Oct 29)

- `link` (new): light `#BC202C` (the reference); dark `#FF727D`, 6.98:1 on `bg` (the reference `#BC202C` is 2.97:1 on `bg`).
- Dark `danger` `#FF727D` and dark `placeholder` `#6D6D78`: the reference values.
- Light `danger` stays `#C43140` (5.0:1 on `bg`): the reference `#DC3545` is 4.16:1 on `bg` `#F6F5F5`.

- WCAG 2.1, contrast (minimum): https://www.w3.org/TR/WCAG21/#contrast-minimum

### D8. Independent check

An independent agent measured the new parts against the reference shots (DOM boxes, pixel colours, border widths, touch areas, focus after a busy request) in light and dark mode. It found no difference other than T9's decisions, and three small faults: an `aria-disabled` on the busy pill that a phone screen reader reads as "disabled", and two notes; all three are fixed in this change.

- Playwright, accessibility snapshots and locators by role: https://playwright.dev/docs/locators#locate-by-role
