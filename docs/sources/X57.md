### D343. The $default route of the SME, and no connection id on $default and $disconnect
- https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-websocket-api-data-transformations.html — the integration request gets only the parameters that the route maps (here `context.connectionId` only on `$connect`). With no `X-Connection-Id` on `$default`, the box cannot know which socket sent a ping, and with none on `$disconnect` it cannot know which socket closed. T9: "we change it" (our code, not the SME's set-up). So: `POST /api/push/pingOn` is the same handler as `/api/push/ping`; the ticket answer also has a `key` (16 random bytes, never in the URL), `$connect` keeps it with the connection, and the app's ping is `{"action":"ping","key":"<key>"}` (the message body goes to the integration as its body). The box finds the connection by the header when it is there, else by the key (compared in constant time), and answers `{"kind":"pong"}` through @connections. An unknown key gets no pong (the app then counts the socket as not working and polls as before; it opens a new socket at its next reopen, 9 min).
- https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-how-to-call-websocket-api-connections.html — a POST to a closed connection answers 410 Gone, and the box forgets it (WS1). For a socket that closed with no id: a connection with no ping (by key or by header) for 3 min since its connect or its last ping (the app pings each minute) is forgotten and closed (DELETE @connections) at the next sweep (an event `push.stale`); this also covers a socket that closed before its first ping.

### D344. The allowed Origin is the new public name
- https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html — an explicit allowlist of trusted origins: the compose value of `-origins` is `V3RDE_PUBLIC_URL`, now `https://v3rde.thehungreeapp.com` (X56), and so is the binary's default; the icarus name has no address. The binary's default auth is `http://auth:8081` (auth stays on TCP here). The Report-Only CSP of the edge (X53) allows `wss://ws-v3rde.thehungreeapp.com` in `connect-src`, so the socket gives no report and works when the CSP is enforced.

Push stays off until the box has `V3RDE_PUSH_ENDPOINT` (`https://<api-id>.execute-api.<region>.amazonaws.com/prod`), `V3RDE_PUSH_URL` (`wss://ws-v3rde.thehungreeapp.com`) and `V3RDE_PUSH_REGION` in `/opt/v3rde/.config/v3rde/push.env` (lines `KEY=value`; the stack script reads only these three keys from it and runs nothing in it), a non-empty `push_secret`, the box role may call `execute-api:ManageConnections`, and the instance metadata hop limit is 2 (WS1 D420). Until then the ticket answers 404 and the app polls as before.

Review (independent, 15 minutes at most): no blocking defect; the key design is sound (a ping needs the integration's secret; a key is one per ticket and only its signed-in owner gets it; constant-time compare; tickets at most 8 per user).
