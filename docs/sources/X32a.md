# X32a — sources for each decision

Change: X32a, the one analysis route. `/v1/analyze` (shared bearer token, plan A) and `/api/analyze` (the app's session cookie) run barcode → food gate → busy → daily cap → SAM 3.1 + Muse Spark → the model's "no food" items dropped → dedup → item photos, in the analyze service (X31's inventory service, renamed). `/api/scan`, `/api/inventory`, `/v1/inventory` and the router are removed. Decisions by T9, 2026-10-27; the approved UI and contract: project doc `docs/icarus_x32_mockup_2026-10-27.md` (mockup artifact version 2). Read 2026-10-27.

Own evidence: T9's Postman call (2026-10-27) to `/v1/analyze` with a non-food photo returned 200 with `"name": "No food"`. The 57 Muse answers in the Morpheus `/v1/analyze` metrics (2026-10-24..27; copied to the Mac before the Morpheus box removal, archive sha `83f5f5031d8f…`) are in `inference/testdata/x32_muse_names.json`: 8 say no food in 5 spellings, 49 are food.

### D43. One route, the same answer shape for one item and for many
- https://www.rfc-editor.org/rfc/rfc9110#name-200-ok — 200 carries the result.
- T9 decisions 2026-10-27: "there are no other routes after this change"; the nested answer `{request_id, source, model, latency_ms, count, items: [{item, fields, photo_id}]}` with the eight contract fields unchanged inside `fields`; `number_of_serving` = the count of identical items; the front-end developer moves to the new contract.

### D44. Every non-200 answer has a fixed `code`
- https://www.rfc-editor.org/rfc/rfc9110#name-422-unprocessable-content — 422 for a photo with no food (`not_food` from the gate; `model_no_food_single` and `model_no_food_multi` when the gate said food but the model found none, T9: "differentiated").
- https://www.rfc-editor.org/rfc/rfc9110#name-409-conflict — 409 `already_listed` (T9: single item = 409; several = the listed ones are dropped and logged).
- https://www.rfc-editor.org/rfc/rfc6585#section-4 — 429 Too Many Requests (`rate_limited`).
- https://www.rfc-editor.org/rfc/rfc9110#name-503-service-unavailable — 503 for `gate_unavailable`, `busy` and `daily_cap_reached` (T9: the cap is production-halting, so 503).
- https://www.rfc-editor.org/rfc/rfc9110#name-410-gone — the removed routes answer 410 `route_removed` with the way forward.

### D45. The model's own "no food" answer is found from its text
- https://dev.meta.ai/docs/image-understanding — the single-item call asks for JSON with exactly the fields in its prompt (analyze.Prompt: the eight listing fields, no food field), so the answer text is the only signal of "no food" there.
- T9 2026-10-27: "lets keep it simple for now": a name such as "No food", "None", "Unknown", or a description that says no food is visible. The single-item prompt is analyze.Prompt, which has no food field.
- Test on the logged answers (`TestModelSaysNoFoodOnTheLoggedAnswers`): the rule finds the 8 no-food answers and none of the 49 food answers; the description rule needs "no … food" AND visible/detected/found/image, so "No added sugar; a healthy food bar." is not matched.

### D46. Rate limit 6 per minute per user; bearer callers per IP
- https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/ — limit how often a client can call an API that costs money.
- T9 2026-10-27: "keep it 6". The token is one shared token (no user), so its limit is per client IP (Caddy `{client_ip}`, X31).

### D47. Item photos: the server cuts the crops and owns the access check
- https://pkg.go.dev/image/jpeg — the crop is encoded at quality 90 (`CropJPEG`, X31) from the uploaded photo at full size, with a 12% margin; a group's photo is its largest instance (T9).
- https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/ — every read of a photo_id checks its owner (analyze `GET …/photo/{id}`, listings `photo_id`); an unknown and a foreign photo_id get the same answer, so ids cannot be probed. photo_id is 32 random hex characters.
- T9 2026-10-27: "this is what i want the server to do"; `POST /api/listings` takes `photo_id`; crops and uploads are kept as a training set.

### D48. Every box is in the ledger
- https://docs.aws.amazon.com/wellarchitected/latest/machine-learning-lens/mloe-07.html — MLOE-07, "Establish a lineage tracker system": keep the lineage of the data that a model is trained on.
- T9 2026-10-27: "every thing must be retracible … we have to log it in ledger". The event line gives every kept SAM box (pixels on the upright stored photo, with its frame), what became of it (item, not_food, model_no_food, already_listed, not_named), the dropped counts, the dedup result, the photo_ids and the exit code; field names follow the router "scan" and the X31 inventory events.

### D49. The item photo folder exists before Docker mounts it
- https://docs.docker.com/engine/storage/bind-mounts/ — a bind-mount source that does not exist is created by Docker on the host (as root), so the stack script creates `$MORPHEUS_PHOTOS/items` and gives it to uid 65534 first.

### D50. Caddy no longer adds the token on `/api/analyze`
- https://caddyserver.com/docs/caddyfile/directives/reverse_proxy — `header_up` was how Caddy added the token; without it, `/api/analyze` needs the app's session.
- Before X32a, `/api/analyze` was open to any caller on the internet (Caddy added the shared token). T9 2026-10-27: `/api/analyze` requires the app's session; only `/v1/analyze` takes the bearer token.
