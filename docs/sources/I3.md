### D425. A static page next to the app, as the About page
- https://docs.expo.dev/guides/publishing-websites/ — `npx expo export -p web` makes the static web bundle; the files of `public/` go into it as they are (checked: an export has `learn/index.html`, the same bytes). No screen of the app changes and the app bundle does not grow.
- The page is the file of the approved mockup: the mockup rendered this file with fake answers of the route.

### D426. The page has no data; the route decides who sees it
- https://api-security.owasp.org/editions/2023/en/0xa5-broken-function-level-authorization/ — the authorization check is on the server: the page file is public, and it reads `/api/analyze/learn` with the session cookie (`credentials: "same-origin"`); a caller who is not an admin gets 404 there and the page shows only "Not found.". `<meta name="robots" content="noindex">` keeps the empty shell out of search engines.

### D427. The report's words go in as text
- https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html — use `textContent` for untrusted data, not `innerHTML`: the report has the donors' titles. The script has no `innerHTML`, `insertAdjacentHTML`, `document.write` or `eval` (a test checks it), and a day goes into a URL only when it is 8 digits.

### D428. The About page's tokens, byte for byte
- https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties — the tokens are CSS custom properties on `:root`, so one block holds every value the rules use (`var(...)`).
- The page copies the About page's token block (fonts, the palette in light and dark, space, radius, size, the widths of `layoutFor`); `tests/learn.test.mts` checks that the block is the same text, and that the rest of the page (CSS, markup, script) adds no colour, no length but the type sizes and breakpoints, and no fraction but the opacity tokens. The About tests check that block against `src/theme.ts`.
