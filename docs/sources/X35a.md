# X35a — sources for each decision

Change: X35a, the photo touch-up service (`post/`, `cmd/touchup`, port 8088). Muse Image 1.0 makes a listing photo look better; Muse Spark 1.3 compares the original and the edit; the edit is offered only when the food did not change, and the original is always kept. Build only: no compose or Caddy route yet (an integration step). Request by T9, 2026-10-28: "what if we have a model touch up photos that have been taken?"; then "create an implementation in go … build but not apply just yet", after a review that recommended light, crop and background changes only, with the original kept. Read 2026-10-28.

Own evidence: 16 Go tests in `post/` (a fake Meta API: the edit request, the check, the stored item photo, owner-only reads, the failure paths, the cap and the busy limit). No live call and no measured time or quality yet.

### D69. Muse Image 1.0 through POST /v1/images/edits, at $0.01 per image
- https://developer.meta.com/ai/resources/blog/build-with-muse-Image/ — Meta: Muse Image on Meta Model API, $0.01 per image; `POST /v1/images/edits` for image-to-image editing; the endpoints mirror the OpenAI Images API (the SDK uploads images as multipart).
- https://www.orcarouter.ai/blog/muse-image — model id `muse-image-1.0`; `size` sets the aspect ratio only; `response_format` b64_json; `output_format` webp by default, png and jpeg available; `reasoning_strength` high by default or low.

### D70. A fixed list of modes; the user never sends a prompt
- https://guptadeepak.com/agent-security/threats/llm01/ — OWASP LLM01:2025 prompt injection: "crafted input changes the model's behaviour against its instructions"; here no user text reaches the edit.
- https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/ — bound what a client can make the server spend: 2 modes, 5 MB images, a rate limit (keyed by the socket peer unless `-trust-forwarded` is set behind Caddy; old keys are removed), 2 jobs at the same time, a daily cap.

### D71. A second model checks the edit; the service fails closed and keeps the original
- https://www.orcarouter.ai/blog/muse-image — Meta says the model "is designed to change exactly what you specify and leave everything else untouched", with no published edit-fidelity benchmark: so we check every edit.
- https://arxiv.org/abs/2306.05685 — Zheng et al., "Judging LLM-as-a-Judge": a strong model can grade another model's output; we use Muse Spark to compare image 1 and image 2.
- https://developer.meta.com/ai/resources/blog/build-with-muse-Image/ — the Responses protocol content list carries images; that one request may carry 2 images (the original, then the edit) is not in the docs we could read. The first live call confirms it; if the API refuses it, the check fails and the original stays.

### D72. A job (202, then GET), not one long request
- https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html — the HTTP API integration timeout is 30 s and cannot be raised (the same limit as X32c, D58); the edit time is not measured yet.
- https://www.rfc-editor.org/rfc/rfc9110#name-202-accepted — 202 Accepted: the request is accepted and the work is not complete.

### D73. The edit is stored in the item-photo format; reads are owner-only, one 404
- https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/ — check the owner of every object; one answer for "unknown" and "not yours", so an id cannot be probed.

### D74. Its own events file and daily cap, at the official prices
- https://dev.meta.ai/docs/pricing-rate-limits — Muse Spark 1.3 token prices (the same constants as `inference/pricing.go`); a failed call is counted as free.

### D75. The listing photo is a JPEG: a PNG edit is re-encoded, any other type keeps the original
- https://pkg.go.dev/image/jpeg — the standard library encodes JPEG; it has no WebP decoder (https://pkg.go.dev/image), so the edit asks for `output_format=jpeg`.
