### D291. The last state of a job and the free listing in one lock
- https://pkg.go.dev/sync@go1.21 — "A Mutex is a mutual exclusion lock"; "the n'th call to Unlock 'synchronizes before' the m'th call to Lock". So when `Done` stores the job's end and clears the listing's mark under one lock, a `Begin` that sees the end also sees the free listing.
- `Done` keeps the R4 review rule: when the file write fails, the job is failed in memory (never "running") and a new POST may run. The `defer End` stays for a panic in the job.
- The same order rule for the tests: a test sees the job's end (`GET`) before the job writes its events line, so the job tests wait for the line (`eventsWith`, at most 5 s) and do not read the file once. Only test code changes.
