### D1. Food gate first (PE-Core-S16-384)
- https://arxiv.org/abs/2504.13181 — Bolya et al., *Perception Encoder* (Meta): the PE-Core model family used for the gate.
- https://huggingface.co/facebook/PE-Core-B16-224 — the PE-Core model cards (Apache-2.0 weights).
- Own evidence: `tools/hackathon/results/deploy_head_20261026T185715Z.json` (X29: AUROC 0.981, catch 0.831, false retake 1.6%); v2 / v3 gate refusals on shelves.

### D2. Barcodes are read on the phone
- https://developers.google.com/ml-kit/vision/barcode-scanning — on-device barcode scanning from live camera frames (the method of the prior product).
- https://docs.expo.dev/versions/latest/sdk/camera/ — the app's camera reads barcodes (`onBarcodeScanned`) on the device.

### D3. SAM counts, Muse names
- https://arxiv.org/abs/2511.16719 — Carion et al., *SAM 3: Segment Anything with Concepts*: one concept prompt returns every instance.
- https://docs.ultralytics.com/models/sam-3 — SAM 3 CountBench 95.6% vs 92.4% for the best multimodal model.
- https://dev.meta.ai/docs/sam/overview — SAM 3.1 on the Meta Model API.

### D4. Two SAM concepts in parallel ("food", "package"), food inside a package joins it
- https://dev.meta.ai/docs/sam/segmenting — one concept per request (a list of concepts gives zero matches).
- Own evidence: v2 vs v3 shelf 6 (10 of 11 pictures → 8 of 8 real boxes); v3 Cheerios / Honey Maid ("food" 0, "package" 15 and 25).

### D5. A tray is one listing
- https://www.webstaurantstore.com/documents/pdf/vigorpan_layouts.pdf — hotel-pan sizes (full, ⅔, ½, ⅓, ¼, ⅙, ⅑) are the units in which cooked food is served.
- Own evidence: v4 shelves 21–22 (one listing per tray); T9 decision 2026-10-26.

### D6. Route by the number of boxes; one item = analyze, byte-for-byte
- https://dev.meta.ai/docs/protocols/responses — the same Responses request analyze makes (prompt + image), sent unchanged.
- Own evidence: `inference/engine_test.go` `TestOneItemPhotoIsExactlyAnalyze`; T9 requirement R1.

### D7. The agent is a fallback
- https://dev.meta.ai/docs/tool-calling — function tools, `tool_choice` auto, `function_call_output` with `previous_response_id`.
- https://arxiv.org/abs/2210.03629 — Yao et al., *ReAct*: a model that interleaves reasoning with tool calls (the agent pattern).
- Own evidence: v1 agent 21 s / photo; v2 20–50 s.

### D8. Resize to Muse's 4,096-token limit ourselves
- https://dev.meta.ai/docs/image-understanding — "the model may resize images"; coordinates "are relative to the image the model actually received"; cost scales with resolution.
- https://dev.meta.ai/docs/token-counting — `POST /v1/responses/input_tokens` for exact counts.
- https://docs.nvidia.com/nemo/automodel/latest/nemo-automodel/nemo_automodel/components/models/muse_spark/image_processing.md — Muse Spark Open image processor: patch 14 × downsample 2, at most 4,096 image tokens.
- https://pkg.go.dev/golang.org/x/image/draw — Catmull-Rom resampling (BSD-3).
- Own evidence: `ie_tokens_shelf14_20261026.txt`.

### D9. Boxes on Muse's 0–1000 grid
- https://dev.meta.ai/docs/image-understanding — "a normalized 0–1000 grid"; "State the exact fields and axis order in your prompt and ask for JSON."

### D10. Numbered marks on the photo + coordinates
- https://arxiv.org/abs/2310.11441 — Yang et al., *Set-of-Mark Prompting*: numbered marks on regions raise referring accuracy (25.7 → 86.4).
- Own evidence: v3 hand check (marks + coords 89.8%, marks only 84.7%, points hit 90% without coordinates).

### D11. One pass, not two
- https://dev.meta.ai/docs/prompt-caching — caching is automatic prefix matching ("Put stable content first"); no guarantee between separate requests.
- Own evidence: v3 (two passes $0.0248 vs $0.0222 per photo, 79.9% vs 89.8%, 0 cached tokens).

### D12. Reasoning effort `low`
- https://dev.meta.ai/docs/reasoning — allowed values; "Use the lowest level that gives you acceptable results"; reasoning tokens billed as output.
- Own evidence: v2 (`minimal` grouped 12 different products as one).

### D13. One retry; no per-crop fallback
- https://arxiv.org/abs/2502.17422 — Zhang et al., *MLLMs Know Where to Look*: crops help when the crop has enough detail; our crops came from small photos (about 100 image tokens each).
- Own evidence: v1 crop mode ($0.0185 / photo, invented items).

### D14. Count everything; name at most 24; three size levels (≥96 / 64–96 / <64 px)
- https://arxiv.org/abs/2502.17422 — multimodal models are less accurate on small objects.
- https://docs.cvedia.com/plugins/processing/cocoeval/index.html — COCO evaluation size ranges (small / medium / large; COCO standard).
- Own evidence: `v3_ground_truth.json` (≥96 px 97.4%, 64–96 px 81.0%, 48–64 px 71.4%, <48 px 46.2%).

### D15. Not food → "not listed", never deleted
- https://pair.withgoogle.com/chapter/errors-failing/ — Google PAIR *People + AI Guidebook*, errors and graceful failure: let the user correct the system.
- Own evidence: v3 (signs, a bin and a cardboard box correctly marked not food).

### D16. Grouping and servings
- https://en.wikipedia.org/wiki/Disjoint-set_data_structure — union-find, used to merge `same_as` links and equal names.
- https://dev.meta.ai/docs/structured-output — ask for one JSON shape and validate it.

### D17. Cost per call, photo and item
- https://dev.meta.ai/docs/pricing-rate-limits — Muse Spark 1.3 $1.25 / $4.25 / $0.15 per 1M tokens; SAM 3.1 $2.50 per 1,000 images.

### D18. Boxes and masks for the screen
- https://dev.meta.ai/docs/image-understanding — dividing 0–1000 coordinates by 10 gives CSS percentages.
- https://dev.meta.ai/docs/sam/reading-segmentation — SAM box and mask output.

### D19. Containers: duplicates by IoU only; holders dropped
- https://arxiv.org/abs/1904.00853 — Goldman et al., *Precise Detection in Densely Packed Scenes* (SKU-110K): overlapping and nested detections in dense retail scenes need their own de-duplication.
- https://en.wikipedia.org/wiki/Jaccard_index — IoU.
- Own evidence: v4 shelf 20 (board over 3 pans → 1 listing before the fix); `TestDropHolders`.

### D20. Tray servings from the pan-size table
- https://www.webstaurantstore.com/documents/pdf/vigorpan_layouts.pdf — Vigor chart: servings per pan by size, depth and ounces (half, 2.5 in: 22 at 6 oz, 34 at 4 oz).
- Own evidence: v4 (the same tray: 30 vs 12 servings from the model).

### D21. Parallel work; split 3 from 12 named boxes
- https://dev.meta.ai/docs/pricing-rate-limits — 3,000 requests per minute.
- https://go.dev/doc/effective_go#concurrency — goroutines and `sync.WaitGroup`.
- Own evidence: v4 (14.9 s → 6.1 s, +35% cost; SAM 32 s summed, 11.6 s wall).

### D22. What SAM is sent (open until X30b)
- https://www.mdpi.com/1424-8220/22/3/1104 — Gandor & Nalepa 2022: detection accuracy flat from JPEG quality 100 to about 40; small objects suffer first.
- https://arxiv.org/abs/1604.04004 — Dodge & Karam 2016: image quality and deep networks.
- https://arxiv.org/abs/2007.14314 — Poyser et al. 2020: lossy compression and CNN performance.
- https://dev.meta.ai/docs/pricing-rate-limits — SAM is billed per image (a smaller photo saves time, not money).
- Own evidence: `sam_size_20261026T234222Z.json`, `sam_size_20261026T235234Z.json`.
