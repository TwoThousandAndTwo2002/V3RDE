### D201. X-Client-Ip first, from a trusted hop only
- https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-parameter-mapping.html — `overwrite:header.<name>` with `$context.identity.sourceIp` sets the header on the request to the integration, in place of the caller's own.
- https://caddyserver.com/docs/caddyfile/options#client-ip-headers — Caddy reads the client address from the listed headers, in order, only when the request comes from a trusted proxy (`trusted_proxies static private_ranges`; Apache and the load balancer are private).
- `header_up -X-Client-Ip` removes it before the services: they keep reading CF-Connecting-IP and X-Forwarded-For, which the edge sets (D150).
- Limit: the header is trusted from any private hop. A caller that could reach Apache without API Gateway could send its own X-Client-Ip. The test script x48b_client_ip.sh checks the public path: a request with a false X-Client-Ip must be logged with the Mac's real address.
