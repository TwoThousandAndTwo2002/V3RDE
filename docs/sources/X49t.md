### D305. Fan-out gets the Page token file and the V3RDE Page ID
- https://developers.facebook.com/documentation/pages-api/getting-started — a Page access token and the Page ID from `GET /me/accounts`; the user needs the task CREATE_CONTENT (fb2 checked it).
- https://developers.facebook.com/documentation/facebook-login/guides/access-tokens/get-long-lived — "Long-lived Page access token do not have an expiration date and only expire or are invalidated under certain conditions"; it comes from a long-lived User token (fb2: expires_at 0).
- The compose file mounts `${V3RDE_CFG}/fb_page_token` read-only at `/run/secrets/fb_page_token` (the fan-out default) and sets `-page-id ${FANOUT_PAGE_ID-1415609644973410}`: the Page ID is public; `FANOUT_PAGE_ID=` (empty) or an empty token file turns posting off (fan-out: "posting off").

### D306. The stack script makes the token file and checks that fan-out posts
- https://docs.docker.com/engine/storage/bind-mounts.md — a missing host path of a `-v` mount is made by Docker, and "It's always created as a directory". So the stack script makes an empty 0600 file (uid 65534) when the token is missing, as for the reset mail files (X49o), and fan-out then does not post.
- After the start: with a token on the box, the fan-out health line must say `"page":true`, else the deploy check counts it as bad. The secret leak check of `docker inspect` also covers `fb_page_token` (security review E12).
- Open (known, T9 chose to start): fan-out checks the post text, not the photo, before a public post; a grab in the same second can leave a post open until the 1-minute sweep; the app is in development mode, and Meta says Page permissions need App Review before users without a role on the app can grant them (https://developers.facebook.com/documentation/pages-api/overview) — the first post shows whether the public can see it.
