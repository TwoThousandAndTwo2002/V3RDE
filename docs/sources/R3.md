### D252. Bulk (30 servings, or the scanner's "bulk" on a vision scan) keeps the email; a drop-off has no draft and no /send
- Bulk: `number_of_serving` >= 30 (T9; compose `RESCUE_MIN_SERVINGS`, default 30; the flag's own default stays 1, so a run without compose does not change), or `details.serving_type` = `bulk` (the scan contract, `server/contract.go`; kept since X48d) on a vision scan only: a barcode answer sets `individual` as a fixed value (`barcode/product.go` `Complete`, provenance `constant`), the same route check as R1 (D250). The bulk prompt is X35b's, byte for byte (test).
- The drop-off prompt asks only `shelf_stable` and `reason` (the place kind needs it); it keeps X35b's rules (no safety claims, no dates). The scanner note (R1) goes in the same place. A drop-off stores an empty draft and no `mailto`; `/send` answers 409 `dropoff`, so the relay never mails for one.
- https://genai.owasp.org/llm01/ — the same untrusted-text rule as D248: the pickup text never goes into a prompt.

### D253. The location from the pickup address's ZIP; no geocoding
- https://feedam.org/api/openapi.json — the Feed America `/api/resources/search` takes `zip` (and `mode`, `type`, `radius`, `limit`); `/api/resources/nearby` takes `lat`/`lng`. No address parameter. So the ZIP of the pickup address is the search key.
- https://pe.usps.com/text/pub28/28apb.htm — USPS Publication 28, Appendix B: the two-letter state, DC, territory and military codes. A US address ends with "city, state code, ZIP"; so a ZIP counts only right after one of these codes (uppercase, or any case after a comma), and the last such ZIP is used. Independent review: a lone 5-digit number is a house, suite or gate code number ("12345 W Colfax Ave", "Suite 10001", "gate code 54321"), so it never counts. A 5-digit group inside a longer number or a phone number is not a ZIP; 00000 is skipped; full-width digits do not count. No ZIP: the body's zip or lat/lng, as before. No geocoding service: none is in the stack.
- The pickup text can be an address: it is never written to the events line (X48u rule); only `location_from` is.

### D254. A Google Maps directions link for each place
- https://developers.google.com/maps/documentation/urls/guide — `https://www.google.com/maps/dir/?api=1&origin=…&destination=…`: origin and destination can be an address; with no origin, Maps starts at "the most relevant starting point, such as the device's location"; "You don't need a Google API key to use Maps URLs"; the URL must be encoded and is at most 2,048 characters. The origin is the address part of the pickup text; the destination is the place name and address; each is cut at 150 runes and then at 900 characters once encoded (independent review: a rune can be 12 characters encoded), so the link stays under 2,048 (test with 2-, 3- and 4-byte runes).
