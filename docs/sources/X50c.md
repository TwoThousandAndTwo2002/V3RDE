# X50c — sources for each decision

Change: X50c (app), the web photo picker: a real file field opened in the tap (`mobile/src/webpick.ts` (new), `mobile/src/screens/Capture.tsx`, `mobile/tests/webpick.test.mts` (new), `mobile/package.json`, `i18n/rules.json`; NEW_WORK.md 95).

T9 (2026-11-01): "on mobile user is not able to upload a previously taken photo"; the phone: Android, DuckDuckGo ("chromium based"); DuckDuckGo on Android shows pages in the Android WebView.

Own evidence: in a phone emulator (Chromium, touch on, the #92 build) "Upload a photo" opens the file chooser and the photo comes in; so the failure is in the real phone's browser, and it was not seen here. The code of `expo-image-picker` 58.0.10 (web, `build/ExponentImagePicker.web.js`) shows two weak points: (1) the file field is `display: none` and is opened with a made-up event (`input.dispatchEvent(new MouseEvent('click'))`), not `click()`; (2) after the choice it waits for the photo to load into an `Image` to read its size, with only an `onload` handler: a photo the browser cannot show makes the app wait with no word (`getImageMetadata`). Limit: the cause on T9's phone is not proved (the DuckDuckGo app opens the Android file chooser itself); T9 checks on the phone after the deploy.

Independent review (fixed): a photo the browser cannot read (HEIC on Android) went to the scan as it was, with no message: it is now refused with "The photo failed. Try again."; the blob address of each upload (and of a dropped file) was not freed: it is; a dropped photo the browser cannot read is refused too. Tests: mobile 170 -> 175.

### D328. A real, off-screen file field and click() in the tap
- https://github.com/whatwg/html/pull/7319 — a browser opens a picker only with transient user activation ("It can only be called with transient user activation"). `pickImageWeb` makes the field in the tap and calls `click()` before any wait; the field is off screen (1 px, opacity 0), not `display: none`; a field of an earlier tap that never answered (no `cancel` event in some browsers) is closed at the next tap.
- https://developer.mozilla.org/docs/Web/API/HTMLInputElement/showPicker — the file picker belongs to the file field; the app keeps the field in the page until the choice or the cancel.

### D329. The file goes straight to the upload step
- https://developer.mozilla.org/docs/Web/API/URL/createObjectURL_static — a chosen File becomes a blob URL with no copy and no decode. The chosen file goes to the same step as a dropped file (`take(URL.createObjectURL(file))`): first the browser must read the photo (`createImageBitmap`; a photo it cannot read, for example an HEIC photo on Android, gets "The photo failed. Try again."), then the upload step makes the upload copy (`photo.ts fromUri`). A file with an image type or with no type (some Android galleries give none) is tried; another type gets the same words. The file's blob address is freed at Start over and when the camera closes (also for a dropped file). The phone build keeps `expo-image-picker`.
