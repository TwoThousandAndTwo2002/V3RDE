# X46a — sources for each decision

Change: X46a, the gate runs with `-threads 2` (`deploy/docker-compose.yml`; NEW_WORK.md 45). Entry number 45: the numbering is shared by the branches, and 44 is on branch LIF (L2).

Own evidence (the X45b box bench, 2026-10-29, the deployed gate image v3rde-gate on LiteRT 2.3.0, the box with 2 vCPU, 50 photos stored on the box, `gatebench` one call at a time):
- 1 thread: median 1,071 ms, p90 1,132 ms. 2 threads: median 595 ms, p90 619 ms.
- Two benches at the same time, 2 threads each: medians 1,124 ms and 1,119 ms (p90 1,222 and 1,302 ms, max 4,356 ms). Two benches at the same time, 1 thread each: medians 1,103 ms and 1,128 ms (p90 1,146 and 1,198 ms).
- The verdicts were the same in all six runs (41 FOOD, 9 NOT_FOOD).

### D190. 2 threads for the gate
- https://aws.amazon.com/ec2/instance-types/t4/ — t4g.small has 2 vCPU and 2 GiB.
- https://github.com/google-ai-edge/LiteRT/blob/v2.3.0/litert/c/options/litert_cpu_options.cc — `num_threads` of the XNNPACK CPU option (X45a, D187).
- One scan at a time gets the gate answer about 0.5 s sooner. Two scans at the same time get the same median as with 1 thread; only the slowest calls are slower (max 4.4 s against 1.4 s). A later change (plan P1) can run the gate at the same time as the Meta calls, so the gate is not first in line.
