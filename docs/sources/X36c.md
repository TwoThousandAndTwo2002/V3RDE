### D114. The build stamp makes every image build again; build only the changed ones
- https://docs.docker.com/build/cache/invalidation/ — "Build arguments do result in cache invalidation"; "Once the cache is invalidated, all subsequent Dockerfile commands generate new images and the cache isn't used." Each Dockerfile has `ARG BUILD` (the commit) just before its final `go build`, so that step runs again for every image on every commit.
- Prior work, X20 (`tools/morpheus_stack.sh`): "every image is stamped with the commit it was built from (events carry it)" — kept: an unchanged image keeps the stamp of the commit it was built from, which is still its code.
- Prior work, S13 / X31 (`x31_box_seq.sh`, `x32_box_seq.sh`): one image at a time, the build cache kept (X23) — kept.

### D115. Start with the images already built: compose up --no-build
- https://docs.docker.com/reference/cli/docker/compose/up/ — `--no-build`: "Don't build an image, even if it's policy"; `--remove-orphans`: "Remove containers for services not defined in the Compose file". With `--no-build`, a missing image stops the start instead of a build that was not planned.
