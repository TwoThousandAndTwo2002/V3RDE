# X32d — sources for each decision

Change: X32d, the web camera at full size. expo-camera's web camera opens the stream with no size and its `takePictureAsync` draws the video frame, so the web app uploaded the browser's default size. After the camera opens, the app asks the track for the camera's largest size; at the shutter it takes a still photo with `ImageCapture.takePhoto()` where the browser has it, else draws the (now larger) video frame; `prepare()` then makes the D28 upload (about 2376 px, JPEG 0.9). Decision by T9, 2026-10-27 ("yes this is what i would like to move forward with x32d"). Read 2026-10-27.

Own evidence:
- Box (2026-10-27, 20:30–20:42 UTC): 18 of 18 photos the web app sent from T9's phone were 480x640 (43–79 KB); the counter photo with 7 food items gave SAM a 640x480 frame, 5 boxes, 3 named items.
- expo-camera 58.0.12, `build/web/useWebCameraStream.js`: `Utils.getPreferredStreamDevice(preferredType)` (no width or height); `build/web/WebCameraUtils.js` `captureImageContext`: `canvas.width = videoWidth` and `drawImage(video, ...)`.
- The real web export in Chromium with a fake camera: before, the track was 640x480 (capabilities width max 3840) and the upload 640x480; after, the track 3840x2160 and the upload 2376x1337 (phone and desktop layouts); the 9 recorded-answer scenarios of X32b pass with no page errors.

### D59. After the camera opens, ask the track for the camera's largest size
- https://developer.mozilla.org/docs/Web/API/MediaStreamTrack/applyConstraints — a live track takes new width/height constraints; `ideal` lets the browser pick the nearest size it has.
- https://blog.addpipe.com/getusermedia-video-constraints.md — "The browser will try to honor this, but may return a different resolution stream"; read the result with `getSettings()`.
- The target is `getCapabilities()` width.max/height.max, else an ideal of 4096 (`streamTarget`, tested).

### D60. A still photo where the browser has ImageCapture, only when turned like the preview
- https://developer.mozilla.org/en-US/docs/Web/API/ImageCapture/takePhoto — takes a single exposure from the video device and returns a Blob.
- https://caniuse.com/mdn-api_imagecapture_takephoto — Chrome for Android supported; Safari on iOS from 18.4; Firefox not enabled.
- The still is used only when it is portrait/landscape like the preview (`sameTurn`, tested), else the video frame: a photo is never sideways, whatever the browser does with the still's orientation (not verified on a phone yet).
