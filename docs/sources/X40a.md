### D150. One caller address on every route (the fix of D135)
- https://caddyserver.com/docs/caddyfile/directives/reverse_proxy — `header_up` "sets, adds (with the `+` prefix), deletes (with the `-` prefix)"; without a prefix it sets a request header, "overwriting any existing values". Caddy "sets or augments" X-Forwarded-For and ignores the caller's values "to prevent spoofing"; other headers pass unchanged.
- https://caddyserver.com/docs/caddyfile/options — `trusted_proxies` reads the client address from `X-Forwarded-For` only for a trusted peer; with `trusted_proxies_strict` the header is read from the right and "The first untrusted IP address found becomes the real client address", because "the left-most IP address may be spoofed by the client".
- https://caddyserver.com/docs/caddyfile/concepts — the placeholder `{client_ip}` is `{http.vars.client_ip}`; `{remote_host}` is the address of the direct peer.
- The services read `CF-Connecting-IP` first, then the first `X-Forwarded-For` entry (D135). Every route now sets both to `{client_ip}`. Before, the sign-in and listings routes sent `{remote_host}` (the address of Apache, the same for every caller), and a caller could send their own `CF-Connecting-IP` to each route.

### D151. Each image has its own build stamp (the fix of D142)
- https://docs.docker.com/build/cache/invalidation/ — "Build arguments do result in cache invalidation." A stamp that changes on every commit makes every image build again; a stamp that changes only with the image's code does not.
- https://docs.docker.com/reference/compose-file/interpolation/ — "Values in a Compose file can be set by variables and interpolated at runtime"; "`${VAR:-default}` -> value of `VAR` if set and non-empty, otherwise `default`". The build argument and the sidecar `-build` both use `${V3RDE_BUILD_<IMAGE>:-dev}`.
- The stamp of an image is the last commit that changed its build context (`git log -1 -- <paths>`), with `-dirty` when that context has changes not committed or new files not in git (the review). For the images built from the repo root, the context is what their Dockerfile copies (`server/*.go`, not its subfolders). A deploy of a commit that does not change an image gives the same stamp, so that image is a cache hit, and its sidecar `-build` shows the commit the service really runs. Before, every sidecar showed the commit of the deploy.

### D152. A holding page until the app is merged
- https://caddyserver.com/docs/caddyfile/patterns — the single-page app pattern: "try files" to see if the requested file exists, "and if not, fall back to an index file" (`try_files {path} /index.html`).
- The services branch has no app yet (it is built on the ui branch). `/` serves `deploy/web/index.html`; `V3RDE_WEB` points the edge at the app's web export when the ui branch is merged. All API routes are live.
- The review: a missing `/_expo/static/*` or `/assets/*` file got the page with a one-year cache. Now the long cache needs the file to be there (Caddy `file` matcher); a missing one gets the page with `no-store` (tested with Caddy 2.8.4).

### D153. The names are v3rde
- https://docs.docker.com/reference/compose-file/volumes/ — "`name` sets a custom name for a volume"; "The name is used as is and is not scoped with the stack name." Without it the project name is added (the old box had `morpheus_morpheus_auth`).
- The project, the images, the volumes (`v3rde_auth`, `v3rde_listings`, `v3rde_rescue`, `v3rde_fanout`) and the settings (`V3RDE_*`) are new names. The sign-in cookie keeps its name, so no user is signed out. The data of the old volumes is put back by the deploy (X39b copied it).

### D154. One stack script for the Mac and the box
- https://docs.docker.com/reference/cli/docker/compose/up/ — `--no-build`: "Don't build an image"; `--force-recreate`: "Recreate containers even if their configuration and image haven't changed". The edge is recreated on each up, because its Caddyfile is a one-file bind mount and a new file is a new inode (the earlier stack script did the same).
- The script makes the two generated secrets when they are missing (0600, owner 65534 on the box), makes the event, spool and photo folders before Docker does (so they are not owned by root), checks the three assets, and checks each route through the edge. It stops with an error when a check is not as wanted, when the compose file or the Caddyfile is not valid, when a build or the start fails (so a sidecar never shows a stamp its service does not run), and when a container of another project holds the edge port (an old stack would answer the checks). It prints no secret: it counts how often the key and the claim hook secret show in `docker inspect` (want 0).
