# X35d — sources for each decision

Change: X35d, the voice posting service (`post/voice.go`, `post/wav.go`, `cmd/voice`, port 8091). On the review list the donor speaks; Muse Voice Transcribe 1.0 turns one WAV utterance into text; Muse Spark 1.3 maps the text to changes of the scanned items in the listing contract only (title, servings, remove, pickup text). The answer is a proposal: the app shows it and nothing posts until the donor taps "Post". With no items, voice makes a voice-only draft whose items need a photo. Build only: no compose or Caddy route, no app change. Decisions by T9, 2026-10-28: "lets build this but only after you review its functionality. use documentation and also reference other projects that have used it. where possible lets reuse public git code"; "yes" to voice without a photo; "we also have to ensure that we are adhering to a strict contract with the title and servings and directions"; "as of now we are not including description". Read 2026-10-28.

Own evidence: 11 Go tests (WAV pass-through and conversion, crafted headers, streaming headers, the speech request shape, the mapping rules and byte limits, the listing contract (every proposal through `listings.Input.Validate`), strict items input, the voice-only draft, every refusal, the cost and its fallback); a 30 s fuzz of the WAV reader (329,094 runs, no failure). A separate review found that go-audio's reader trusts the header sizes (a 64-byte file allocated 8 GB); fixed before commit (D88). No live call yet: the latency and the transcript quality are not measured.

### D86. Muse Voice Transcribe 1.0, the batch endpoint, one utterance
- https://dev.meta.ai/docs/speech-to-text — `POST https://api.meta.ai/v1/asr/transcribe` (multipart, Authorization header); model `muse-voice-transcribe-1.0`; `PUSH_TO_TALK` = single-turn transcription (the default); 32 MB and 10 minutes per request; $0.18 per hour of audio, billed in whole seconds; failed and 429 requests are not billed; 25 languages.
- https://www.orcarouter.ai/blog/muse-voice-transcribe — no word-level timestamps and no confidence scores; keywords bias recognition but do not guarantee spelling.

### D87. The request shape comes from Meta's own cookbook (MIT)
- https://github.com/meta-models/meta-model-cookbook — `06_muse_voice/01_voice_api_fundamentals/utils.py` (commit 0a99b98): the settings travel as a JSON part `request` {mode, model, audioEncoding "WAV", keywords, languageBias}, the file as the part `audio`; "the server ignores an unrecognised mode rather than rejecting it", so the mode is a constant.
- No public Go client for this endpoint was found; the Go client follows that Python code.

### D88. WAV only: our own strict reader; sent byte for byte when it already matches, else rewritten with go-audio/wav
- https://dev.meta.ai/docs/speech-to-text — the batch endpoint accepts "a RIFF/WAVE container with mono, 16-bit integer PCM at 16 kHz or 24 kHz"; other formats must be converted first.
- https://github.com/go-audio/wav — the WAV encoder (Apache-2.0; its licence and those of go-audio/audio and go-audio/riff ship in the image under /licenses). Its reader allocates the chunk sizes the header claims and takes the length from header fields, so reading is our own parser: every chunk must fit in the received bytes (a data chunk of size 0 or 0xFFFFFFFF, as streaming recorders write, runs to the end of the file), and the length comes from the samples. Stereo and 8–48 kHz PCM are mixed to mono and resampled to 16 kHz; compressed audio (WebM/Opus, AAC) is refused, so the app records WAV.
- https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/WAVE.html — the RIFF/WAVE layout: the fmt chunk is 16, 18 or 40 bytes; 0xFFFE is WAVE_FORMAT_EXTENSIBLE, whose SubFormat GUID gives the format; samples of 1–8 bits are offset binary, larger ones two's-complement; odd-sized data has a pad byte.

### D89. The item titles bias recognition; the device language biases the language
- https://dev.meta.ai/docs/speech-to-text — `keywords` (an array of strings) and `languageBias` (an array of language names; a hint, not a forced setting).
- https://www.rfc-editor.org/rfc/rfc5646 — the device tag (BCP 47, as #15 logs it) gives the language name; an unknown tag sends no bias.

### D90. A proposal, checked by code; the photo stays the source of truth
- https://github.com/meta-models/meta-model-cookbook/tree/main/06_muse_voice/02_voice_chess_cua — Meta's voice example turns speech into an action only through "a deterministic local parser" that "accepts only the exact" grammar, and partial or stale transcripts "cannot authorize a move".
- https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/ — "apply proper input validation on responses coming from the model": only items that exist, servings 1–99, the listing field lengths, no new items when the scan has items; everything refused is listed in `dropped`.

### D91. The items, the pickup text and the transcript go to the model as data
- https://guptadeepak.com/agent-security/threats/llm01/ — prompt injection: "crafted input changes the model's behaviour against its instructions"; each value is a JSON value, marked as data.

### D92. One request, not a job: 60 s of audio at most, 25 s for both calls
- https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html — the 30 s integration limit (as X32c); a short utterance and one low-effort Muse call should fit; the first live calls measure it.

### D93. The ledger keeps the transcript and the proposal, never the audio
- https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-protection-principles/a-guide-to-the-data-protection-principles/data-minimisation/ — "adequate, relevant and limited to what is necessary": the transcript is the label for tuning (#15); the audio is not kept.

### D94. The listing contract only, imported from listings/ so it cannot drift
- https://go.googlesource.com/website/+/refs/heads/master/_content/doc/modules/gomod-ref.md — "a local directory should be used as a replacement for all versions of the module" (`replace … => ../listings`, with a matching require), as `inference` imports `../server` for the analyze contract (R3); the limits are `listings.MaxTitle`, `MaxServings`, `MaxPickup`, and a test runs every proposal through `listings.Input.Validate`.
- https://go.dev/src/encoding/json/stream.go — `DisallowUnknownFields` makes the decoder "return an error when … the input contains object keys which do not match" the struct: the `items` input accepts only `item`, `title`, `number_of_serving`; the model's extra keys (for example `description`) are dropped and listed.
