### D416. A unix socket in a volume that only the stack's services mount
- https://www.man7.org/linux/man-pages/man7/unix.7.html — "On Linux, connecting to a stream socket object requires write permission on that socket". The sockets are mode 0660, owned by 65534 (the services' user), in the named volume `v3rde_sock` at `/sock`. Only auth, gate, barcode, ledger (the servers) and analyze, listings, touch-up, rescue, fan-out, voice (the clients) mount it. A test run on a real docker daemon: a container with another uid got "permission denied".
- https://docs.docker.com/engine/storage/volumes/#mounting-a-volume-over-existing-data — a new volume gets the content and owner of the folder in the image: each of the 7 images now has `/sock`, owned by 65534 (as `/events`). Caddy does not mount the volume and keeps TCP to auth (`/api/auth/*` is public through Caddy anyway).

### D417. Servers: -socket, and -listen "" for the socket only
- https://pkg.go.dev/net#Listen — `net.Listen("unix", path)`. One `http.Server` serves the TCP address and the socket (`Serve`, the same handler, the same timeouts). A socket file left by an earlier run is removed at start; any other file at the path stops the start.
- auth: TCP (Caddy) and `/sock/auth.sock`. gate, barcode, ledger: `-listen ""` and their socket: no TCP port, so another container on the network gets no answer from them (the stack check asserts it).
- `-probe-socket <path>`: the binary asks its own health route over the socket and exits (0 = 200). The stack check runs it in the service's container (`docker compose exec`), because the images have no shell and Caddy cannot reach a socket it does not mount.

### D418. Clients: the URL scheme http+unix
- Go source `net/http/transport.go` (https://pkg.go.dev/net/http#Transport.RegisterProtocol): "RegisterProtocol can be used by other packages to provide implementations of protocol schemes". `EnableUnixURLs` adds `http+unix` to `http.DefaultTransport`, which the internal clients use: `http+unix://auth.sock` is the socket `/sock/auth.sock`. The Meta API clients have their own transport (`MetaTransport`) and do not change. A name with `/`, `\` or `:`, and the names `.` and `..`, are refused, so a URL cannot reach a file outside `/sock`; a redirect never leads to a socket (the request of a redirect is refused), so a third-party host that a client follows cannot send it to a socket. Idle connections are kept (16 per socket).
- Compose: `-auth http+unix://auth.sock` in the 6 clients, `-gate http+unix://gate.sock` and `-barcode http+unix://barcode.sock` in analyze. Other calls (listings, fan-out) stay on TCP.

Own evidence: tests in each module (a socket server and the probe, a stale socket, a plain file at the path, mode 0660, a 503 probe, no address; the client transport, the same connection used again, bad names, a plain http URL; the helper file is the same in the modules that share it).
