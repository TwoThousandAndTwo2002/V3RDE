### D316. Every app text is in a word table, as a whole message
- https://webtranslateit.com/learn/locales/icu-messageformat-guide — "Put the whole sentence in one message. Concatenating a translated fragment onto a formatted number defeats the entire point." (also the LIF hand-off to the app, items 1, 3 and 6: whole messages, user words for errors, stable ids). The 76 texts that were inside functions (for example "Post " + plural(n, "listing", "listings")) are now entries of word tables (COUNT, SCAN, NET, CARD, MIC, UNITS, GRAB, SOURCE_NOTE), one text for each case ("Post 1 listing", "Post {n} listings"). The id of a text is "<TABLE>.<key>" (or "<TABLE>.<key>.<case>"), as the extractor gives it. Errors that are never shown (the Maps loader, the camera canvas, the poll URL) are not text (`i18n/rules.json`).
- Two rule files: `i18n/rules.json` is for the app of the deployed tree (cmd/round); the extractor fails on a rule that matches nothing. The frozen LIF files (`en.json`, `graph.json` from the ui commit in `source.json`) keep their own rules (`rules_ui.json`, the earlier `rules.json` byte for byte), so `TestFilesUpToDate` still compares them with the same input.

### D317. The app puts the tables in the chosen language at run time
- https://claude.ai/artifact/7JKNu36AL55J32rEoSXUsT — the approved mockup (T9) shows it with the box's real files: the translated screens, and the new texts in English until the next round. The box publishes `/i18n/index.json` and `/i18n/<code>.json` after each round (X49b). `src/lang.ts` loads the file of the chosen language and the English file of the same round; a string gets the translation with its values put back (the English string is matched to its English template, for example "8 characters or more" -> {MIN_PASSWORD} = 8); a word function still runs in English, and its English text is matched to the English template of each case, then the translation of that case is filled. A text with no translation (or an empty one) stays English. English is always the base, so a second language does not build on the first.

### D318. The first language: the saved choice, then the browser's languages
- https://ligm.univ-eiffel.fr/~forax/MDN/developer.mozilla.org/en-US/docs/Web/API/Navigator/languages.html (a copy of MDN) — `navigator.languages` "returns an array of strings representing the user's preferred languages", "ordered by preference with the most preferred language first". The app takes the first one it has (the exact code, then the same language: es-MX -> es-419, pt-PT -> pt-BR, zh-CN -> zh-Hans; not zh-TW), else English. The choice is kept in the browser (`v3rde.language`); the first screen waits at most 1.5 s for the words.

### D320. Arabic reads right to left
- https://github.com/necolas/react-native-web (react-native-web 0.21.4, as installed): `StyleSheet/preprocess.js` maps `marginStart`, `paddingEnd`, `start`, `end` to the inline-start and inline-end properties, and `createElement` gives a View with `dir` a LocaleProvider, so its children flip. ### D321. Plural cases
- https://www.unicode.org/cldr/charts/46/supplemental/language_plural_rules.html — Arabic has zero, one, two, few, many and other; Hindi one and other; Chinese other only. The English tables have the cases "1" and "more than 1", so each language translates those two cases; Arabic uses its "more than 1" text for 2 and more (a limit; a fix needs English texts for more cases or a translation of each plural form in the rounds).
