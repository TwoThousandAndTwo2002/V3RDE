### D296. listings asks fan-out to post each new listing, with the giver's own session
- https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/ — the object check uses the logged-in user. The hook calls the existing route `POST /api/fanout/{listing_id}` with only the giver's session cookie (no other header or cookie of the request), so fan-out does the same owner check and the same rate limit and daily caps as a tap would. No new secret and no new route.
- In the background after the 201. It tries again (at once, then after 5, 20 and 60 s) on no answer, 429, and a 5xx other than 503: fan-out's `Begin` answers 409 `already_posted` (or `conflict` while one runs) to a second post, and those answers come before the model calls, so a try again never makes a second post (review). 503 (no Page), 409, 404 and other answers end it. The listing id must have the form `l_` + 16 hex characters before it goes into the URL path.
- A test account's listing (X44h, `-test-ttl-emails`) is never posted.

### D297. On by default in compose; it posts only when the Page is set
- https://docs.docker.com/compose/environment-variables/env-file/ — `${VAR-default}` is "value of `VAR` if set, otherwise `default`" (the `:-` form also takes the default when the value is empty). So `-share ${FANOUT_SHARE_URL-http://fanout:8090/api/fanout/}` is on by default and `FANOUT_SHARE_URL=` (empty) turns it off; `-link-base ${FANOUT_LINK_BASE-https://icarus.thehungreeapp.com/l/}` gives the claim link of N4.
- Until `FANOUT_PAGE_ID` and the Page token are set (T9: "when we get facebook page we will configure it"), fan-out answers 503 before any model call: the hook costs nothing and logs the answer.
