### D339. Drop all capabilities; no new privileges
- https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html — Rule 3: "The most secure setup is to drop all capabilities `--cap-drop all` and then add only required ones"; Rule 4: "Always run your docker images with `--security-opt=no-new-privileges` in order to prevent privilege escalation." The Go services run as uid 65534, listen on ports above 1024, and have no setuid step, so none is added back.

### D340. Not caddy and not the lif job, not read_only yet
- https://cheatsheetseries.owasp.org/cheatsheets/Docker_Security_Cheat_Sheet.html — the same page also asks for a read-only file system; that needs more work (below), so it is not in this change. caddy runs as root and binds port 80; the lif job runs as root (A9). They stay as they are. `read_only: true` needs a list of the folders each service writes (temporary files of multipart uploads among them); it is a later change.

Review (independent, 15 minutes at most, with X53): OK. The 19 services have both keys and caddy and lif have neither (PyYAML); the 7 images run as 65534 with no root entrypoint; the sidecars read only `/proc/<pid>/stat` and `/status` (`telemetry/proc.go`), which need no capability. One weak point, not changed: the test reads the compose file as text, not as YAML (the mobile tests have no YAML parser).
