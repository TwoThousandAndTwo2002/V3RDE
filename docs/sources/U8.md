# U8 — sources for each decision

Change: U8 (branch `ui`), the sign-in screen of V3RDE.

### D1. The earlier sign-in screen as the reference to measure

The layout, the states and the behaviour follow the earlier sign-in screen (Icarus `457a62c`), rendered once by a harness as a reference (U6 D1). No code of it is carried; the rewrite guard checks the new files.

- U6 field-parts review (the reference shots): https://claude.ai/artifact/8NFT49XjsyfdcD1TSWXotk

### D2. A 401 offers "Create one", for an unknown email and a wrong password alike

The auth service answers 401 for both, so the screen tells nothing about which accounts exist.

- OWASP Authentication Cheat Sheet, authentication and error messages: https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#authentication-and-error-messages

### D3. The email check is the auth service's check

The screen uses the same loose form as the auth service on branch `services` (`auth/auth.go`, `emailForm`: something@something.something, no spaces), and trims the ends, so the screen and the service agree.

- V3RDE auth service (branch services): https://github.com/TwoThousandAndTwo2002/V3RDE/blob/services/auth/auth.go

### D4. Input settings for the browser and the phone keyboard

The email field: email keyboard, `autocomplete="email"`, no capital. The password field: no auto-capital, no auto-correct, no spell check, `current-password` (and `new-password` after "No account found"), Enter submits and keeps the focus (`submitBehavior` on a phone, `blurOnSubmit` on the web).

- MDN, autocomplete values (current-password, new-password): https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/autocomplete
- React Native, TextInput (submitBehavior, textContentType, autoComplete): https://reactnative.dev/docs/textinput

### D5. One request at a time; the busy pill keeps the focus

A ref stops a second request before the next render (Enter or "Create one" while the pill waits). The busy pill keeps the focus (U6 D6) and has the name "Signing in…".

- React, useRef: https://react.dev/reference/react/useRef

### D6. The wide-screen handoff

After sign-in the card fades out in 300 ms and rises 40 pt (the earlier values), then the next screen comes.

- React Native, Animated.timing: https://reactnative.dev/docs/animated#timing

### D7. One independent check

T9 (Oct 29) set at most one independent check of at most 15 minutes, with the issues told to T9 in plain words before any second run. The check found no layout difference over 1.0 pt and 6 faults (focus after Enter, the handoff did not run, password keyboard settings, new-password, the busy name, an email of spaces); all are fixed and checked with Playwright in the real app.

- Playwright, locators and assertions: https://playwright.dev/docs/locators
