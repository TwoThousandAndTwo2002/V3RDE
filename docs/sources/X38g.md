# X38g — sources for each decision

Change: X38g, the food gate (`gate/`: the PE-Core gate on LiteRT, with Pillow's decode and resize) written new for V3RDE (NEW_WORK.md 30). Decisions by T9, 2026-10-28: rebuild the parts that existed before the Hackathon as new code ("b"), "yes lets move on to the food gate table". Read 2026-10-29.

Own evidence (2026-10-29, Go 1.24.7, LiteRT 1.4.0 x86_64, libjpeg-turbo 2.1.5): an independent review (an agent that did not write the code) compared the old and the new code. Its findings are fixed and have tests. The old gate tests pass on the new code (not committed). The tests: 26 without the build tags, 29 with `litert turbojpeg` (these run in the image build), also with `-race` and with `GOEXPERIMENT=cgocheck2`.

### D144. Write the gate new; keep its routes, answers and events
- https://docs.docker.com/build/cache/invalidation/ — the tests with the tags run in the image build before `ARG BUILD`, so a gate whose decode, resize or model call is not right does not build, and a new commit with the same code does not run them again.
- The exported API (Head, ParseHead, Head.Verdict, PreprocessSpec, Embedder, Config, New), `/healthz`, `/v1/gate`, the JSON answer, the 503 when busy or not loaded (it fails closed), the shadow gate and the events lines are kept, so the services that call the gate do not change.

### D145. The defaults are the PE-Core-S16-384 gate
- https://huggingface.co/facebook/PE-Core-B16-224 — the PE-Core model cards (Apache-2.0 weights), as cited in docs/sources/X30.md; PE-Core-S16-384 is the gate model of NEW_WORK.md 1 to 3.
- D32 (docs/inference_engine_design.md, T9 2026-10-26): "PE-Core-S16-384 is the only gate"; "The earlier gate is not deployed on the Icarus box (research-only weights)." The old gate's defaults were the earlier gate (`gate_s0_f32_192.tflite`, `gate_head.json`); the new defaults are `gate_pe_s16_f16w_384.tflite` and `gate_head_pe_s16_384_deploy.json` with the pins `c0618012…` and `7ba764ea…` of `tools/hackathon/results/export_20261026T183051Z.json` and `deploy_head_20261026T185715Z.json`.
- A shadow gate now needs both of its pins on the command line; the old code had default shadow pins. The deploy change must give them if it starts a shadow.

### D146. The LiteRT library is pinned for each CPU type
- https://docs.docker.com/extensions/extensions-sdk/extensions/multi-arch/ — "you can add architecture-specific binaries depending on the `TARGETARCH` in the extension's `Dockerfile`" (`ARG TARGETARCH`).
- https://pypi.org/project/ai-edge-litert/1.4.0/ — the x86_64 and the aarch64 wheels hold different `libLiteRtRuntimeCApi.so` files. Both were downloaded on 2026-10-29 (`pip download --python-version 3.12 --platform manylinux_2_17_x86_64 / manylinux_2_17_aarch64`) and hashed: amd64 `f421e16d…`, arm64 `23781d01…`. The old Dockerfile had only the amd64 pin, so an ARM box (for example t4g) could not build it. A CPU type with no pin stops the build.

### D147. No Go pointer to unpinned Go memory goes to C
- https://pkg.go.dev/cmd/cgo#hdr-Passing_pointers — "Go code may pass a Go pointer to C provided the memory to which it points does not contain any Go pointers to memory that is unpinned." (the same text is in `go doc cmd/cgo`, Go 1.24.7).
- A new test runs a tiny model (`testdata/tiny.tflite`, 8x8x3 in, 4 out, made by `testdata/make_tiny.py` with TensorFlow 2.21.0) and compares it with TensorFlow Lite's Python interpreter (`testdata/tiny_ref.json`, max difference 1e-5, two runs). It found that a first version of the new `litert.go` passed such a pointer; every C out-value is now a local variable. The test also checks a short input, Embed after Close and a missing file.
- The review: the options object is freed when the open fails, Close takes the lock, and a model whose shapes do not agree with its head is closed.

### D148. Decode and resize are Pillow 12.3.0's, to the byte
- https://github.com/python-pillow/Pillow/blob/12.3.0/src/libImaging/Resample.c — read in the Pillow 12.3.0 source package (`pillow-12.3.0.tar.gz`, sha256 `3b8182a7…`): `#define PRECISION_BITS (32 - 8 - 2)`, bicubic `#define a -0.5`, and the weight `filterp->filter((x + xmin - center + 0.5) * inv_filterscale)` with `inv_filterscale = 1.0 / filterscale`. The Go resize uses the same integer weights and the same product (not a division).
- The goldens in the tests are Pillow 12.3.0's own output (`testdata/gold.py`, `gold2.py`): square and non-square photos, bilinear and bicubic, the JPEG decode through libjpeg-turbo, and the full PE tensor of one photo. A photo with more than 50 million pixels is refused before it is decoded.
