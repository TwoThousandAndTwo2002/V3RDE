### D233. DELETE /api/listings/{id}: the owner only, and only before a grab
- https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/DELETE — DELETE removes the resource; 204 No Content when there is nothing to return.
- https://lab.wallarm.com/api12023-broken-object-level-authorization/ — OWASP API1:2023: every object route checks that the caller owns the object; another user's id answers 404, as an unknown id, so ids cannot be probed.
- A grab is a promise to a receiver: a grabbed listing answers 409 and stays. The data file is saved first; the photo file goes only after the save, and only a file inside the photos folder (independent review: a photo_file of "." or ".." never removes the folder).
- Independent review (app): one delete for a fast double tap; the popup stays open while it deletes; a 404 (already deleted on another device) says "Deleted".

### D234. Fan-out hears "expired" after a delete
- The claim hook (hook.go, X35) already tells fan-out a grab ("claimed"); fan-out takes "claimed" or "expired" (post/fanout.go). A deleted listing's page post says the food is gone, as an expired one, in the background with the same retries.
- https://developer.mozilla.org/en-US/docs/Web/HTTP/Status/409 — 409 Conflict: the request conflicts with the state of the resource (it was grabbed).

### D235. The confirm is a small popup
- https://m3.material.io/components/bottom-sheets/overview — a bottom sheet holds supplementary content and actions; a short confirm needs only a short sheet.
- T9 (quoted above): the small popup class on a phone. `Popup` gets `small`: the small sheet height (`size.sheetSmall`, the same as the small `Sheet`), no new token.
