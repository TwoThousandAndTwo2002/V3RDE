### D163. /v1 takes the token, /api the session, and each sees only its own
- https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/ — "check if the logged-in user has access to perform the requested action on the record."
- Touch-up now does what voice already did (`post/voice.go`: the path picks the kind of caller). A bearer caller owns the photos of `/v1/analyze` (user `""`) and its jobs are marked as bearer jobs; a session user never has an empty id (`AuthClient` refuses it), and `ReadItemPhoto` still refuses `""`, so the two kinds cannot read each other's photos or jobs. The flag on the job is a second check: a test mutation that removes it is not caught, because the user id check already refuses.

### D164. The token can spend only what the daily caps allow
- https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html — calls arrive through API Gateway (30 s per request); until the SME's `X-Client-Ip` setting is in (X40f), all bearer callers share one rate-limit address.
- X36a kept these routes closed because the analyze token is in the app bundle, so anyone with the app can read it. T9 opened them on 2026-10-29. What a token holder can spend is limited by each service's daily cap (touch-up $2, voice $1) and the per-address limits (touch-up 4, voice 10 per minute).
