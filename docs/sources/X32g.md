# X32g — sources for each decision

Change: X32g, the user's corrections in the ledger. After the user acts on an answer, the app sends what they did — for every item of the answer, the model's title and servings, the final ones, and whether it was kept; posted, retake or closed; the device's language tag — to `POST /api/analyze/labels` (bearer: `/v1/analyze/labels`). The analyze service checks and bounds it and logs it as a `labels` event with the answer's request_id, next to the answer's own event. Decisions by T9, 2026-10-27: "we need to be able to utilize our rewind feature - the full tracibility ledger to learn better calibrations"; "lets do that update to ensure we are logging the corrected labels"; "likely we are going to be translating the app in different languages" (hence the language tag). Read 2026-10-27.

Own evidence: the survey (project doc `docs/icarus_multi_item_survey_2026-10-27.md`, live doc https://claude.ai/artifact/7pHBSJm1cK4SLbQekqYLLB) ranks "log the review-list result per post" first, because every later threshold change needs labels. The real web export in Chromium (recorded answers): a multi-item post sent one report with items 1–6, item 5 (removed) `kept:false`; a single post sent `kept:true`; "Start over" sent `retake` with every item `kept:false`; the 9 X32b scenarios pass with no page errors.

### D66. The user's own corrections are the labels
- https://arxiv.org/pdf/1901.07249 — RPC: models tuned on photos unlike the ones in use got 0.02% of real checkouts right; tune on in-use photos.
- https://web.cs.ucla.edu/~ravi/CS239_W20/papers/chameleon.pdf — Chameleon re-tunes settings on recent inputs; that needs an outcome for each input.

### D67. One report per answer, checked and bounded, logged next to the answer
- https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/ — bound what a client can make the server store: 16 KB, 24 items, 120-character titles, servings 0–99 (`CheckLabels`, tested).
- https://www.rfc-editor.org/rfc/rfc9110#name-204-no-content — 204 for a stored report with nothing to return.

### D68. The device's language tag goes with each report
- https://www.rfc-editor.org/rfc/rfc5646 — BCP 47 language tags (en-US, zh-Hant-TW); the service accepts only that shape.
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/resolvedOptions — `resolvedOptions().locale` gives the device's tag in the app.
