# X38f — sources for each decision

Change: X38f, the telemetry (`telemetry/`: the sidecar of each service and the ledger) written new for V3RDE (NEW_WORK.md 29). Decisions by T9, 2026-10-28: rebuild the parts that existed before the Hackathon as new code ("b"), "okay please proceed with the telemetry rebuild". Read 2026-10-28.

Own evidence (2026-10-28, Go 1.24.7): an independent review (an agent that did not write the code) fed the same events files, fake /proc trees and spools to the old and the new code (300 random runs: part lines, blank and CR lines, lines that are not JSON, replaced shorter files, two days and a UTC midnight) and compared the spools, the ledger files, the offsets and the trace answers byte for byte (times masked). It found two small differences (the /proc path form and the rounding of impossible CPU values); both are now the same as before, and its test passes on the new code. The 7 tests of the old telemetry pass on the new code (not committed).

### D139. Write the telemetry new; keep its files, its signals and its route
- https://www.mankier.com/5/proc_pid_stat — utime (14), stime (15) and starttime (22) are "measured in clock ticks (divide by sysconf(_SC_CLK_TCK))"; comm (2) is "The filename of the executable, in parentheses", so the fields are counted after the last ')'.
- The spool lines (event, sample, lifecycle), the ledger files (one per day), the offsets file on the volume (`{"offsets":{...}}`), the lifecycle signals (started, down, up, restarted) and `GET /v1/trace/{id}` are kept, so the sidecars on the box go on from their saved positions.

### D140. The lines are on the disk before their offsets are saved
- https://pkg.go.dev/os@go1.24.7#File.Sync — "Sync commits the current contents of the file to stable storage." The review found that after a power cut the offsets could be saved while their lines were lost, and that an empty offsets file stopped the start. Now the spool (and the ledger) file is synced before the offsets are saved, and the offsets temp file is synced before the rename.

### D141. One bad file or line does not stop the rest
- https://pkg.go.dev/encoding/json@go1.24.7#Valid — a ledger line that is not JSON (a torn line, or the last line while the merge writes it) is left out of a trace answer; before, one such line made the answer an empty body.
- A spool file that cannot be read is logged and skipped; before, it stopped the merge of every spool after it.

### D142. Open items (the old code has them too)
- https://docs.docker.com/reference/compose-file/services/ — the sidecar's `-build` comes from the compose file; when a deploy builds only the changed images, a kept service is labelled with the new commit. This is for the deploy change.
- A line of 64 MiB or more with no '\n' stops the shipping of that file; a re-shipped line (at least once) can show two times in a trace.
