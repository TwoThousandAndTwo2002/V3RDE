### D379. A folder serves its own index.html; the address with no slash goes to the folder
- https://caddyserver.com/docs/caddyfile/directives/try_files — `try_files` rewrites to the first file in the list that exists; "To match directories, append a trailing forward slash `/` to the path". `{path}` alone never matches the folder `about/`, so `/about/` fell to `/index.html` (the app). Now `try_files {path} {path}/ /index.html`, and `file_server` serves the folder's `index.html`.
- https://caddyserver.com/docs/caddyfile/directives/redir — `redir /about /about/?{query} 308` (and `/learn`): a permanent redirect that keeps the method and the query (measured: `/about?x=1&y=2` → `/about/?x=1&y=2`, `/about` → `/about/`); the page's relative links (images, the Learn page's script) then work.
- Measured with Caddy v2.8.4 (the box's version) serving this web build: before, `/about/` and `/learn/` gave the app; after, `/about/` gives "About V3RDE", `/learn/` "Learn report", `/about` 308 to `/about/`, and `/`, `/give` and `/about/x` still give the app. The Learn page's data stays admin only (`/api/analyze/learn` is a plain 404 for other callers, LR3).
- Test: "X67: the about and learn pages are served as themselves, with no sign-in".

Review (independent, 10 minutes at most; Caddy v2.8.4 with the old and the new file, dummy upstreams, the real web build): no defect in the goal, the cache headers (no-store on the pages; immutable only on real hashed files), the security headers and CSP (on every answer, also the 308s), the other routes (API, `/i18n/*`, `/healthz`, push: they come first), path traversal (none; no folder lists). Two small findings, both fixed: the redirect dropped the query (now kept); a folder of the build with no page (`/_expo/`, `/assets/`) is now an empty 404, not the app (the entry says so; no app route uses these names).
