### D285. No region limit on the address search
- https://developers.google.com/maps/documentation/javascript/reference/autocomplete-data — `includedRegionCodes` is optional, "up to 15 CLDR two-character region codes"; "an empty set applies no restriction". With no `locationBias` or `locationRestriction`, "the results will be biased by IP address", so a user in Lagos gets Lagos addresses first.

### D286. No ZIP code anywhere in the app
- T9: "lets drop zip code", scope "Everywhere". The listing keeps the address text and its point (`fetchFields` asks only `formattedAddress` and `location`); Receive, the review and rescue use a point (the phone location, or the point of the address); no screen asks for a ZIP. A saved ZIP choice on a device is no choice (the app asks for the location again). The services still accept a ZIP from an old app and keep the US ZIP table (open: a later cleanup).
- https://developers.google.com/maps/documentation/javascript/reference/place — `Place` fields `formattedAddress` and `location`.

### D287. The rescue web search names no country
- The pickup address can be in any country (D285). The web search of rescue (R4) runs when the US food bank directory has no places, which is always the case outside the US; its prompt asked for places "in the United States" with a "street, city, state ZIP" address. Now it asks for places near the point, with "the full postal address", and names no country. A test checks it.
- https://developers.google.com/maps/documentation/geocoding/requests-geocoding — a postal address has a different form in each country (the `country` component, the sample answers for the US and the UK), so the prompt asks for the address as the place's own country writes it.

### D288. Location off: all food with no distance; Post and rescue ask for the location
- With no ZIP, a place can only be a point. Receive: "Not now", or a location the browser does not give, shows all food with no distance (the listings service gives the live list without a place, as before X49e) and a link to try the location again. The review without the address search takes the location at Post ("Location is off. Turn it on … then post again."). Rescue of a listing with no point offers the giver's location.
- https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition — the browser can refuse or fail (`PERMISSION_DENIED`, `POSITION_UNAVAILABLE`); the app shows the "Location is off" words then.

### D289. The map moves; the pin stays in its centre
- https://developers.google.com/maps/documentation/javascript/interaction — `gestureHandling`: "greedy" "reacts to all touch gestures and scroll events" (one finger moves the map on a phone; "cooperative" needs two fingers); the zoom buttons stay (`zoomControl`). The pin of the app stays in the centre, so the pickup point is the map centre each time the map stops (the "idle" event).

### D290. "Use my current location", and the address follows the pin
- https://developers.google.com/maps/documentation/javascript/geocoding — `importLibrary('geocoding')`, `new Geocoder().geocode({ location })`, `formatted_address`. The same browser key (the Geocoding API is on for it since x49m).
- A map move asks the address only when the pin moved more than `ADDRESS_FOLLOW_M` (20 m) from the point of the address text, `NAME_WAIT_MS` (500 ms) after the map stops (fewer requests), and only the answer to the last move counts. While it runs, "Finding the address…" shows and Post waits, so the text always matches the pin; with no address for a point, the text is its coordinates. The address of a point is the nearest address Google knows (in a large building it can be the next one); the giver can type a new address.

### D291. The address card is the change button; the large map
- T9: no "Change the address" link; a tap on the address card opens the change: the block moves to the top of the page (`scrollIntoView`, block "start"), the field holds the address, and the map grows to the new token `size.mapTall` (320, 2 × `size.mapH`); a tap outside the block closes it (T9's choice). The "choose" error is under the field.
- https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollIntoView — `block: "start"`, `behavior: "smooth"`.
- https://www.w3.org/WAI/ARIA/apg/patterns/button/ — the card is a button with a name ("Change the address, …").

### D292. The chat hints take turns in the box
- T9: the hints "appear and disappear in the dialoge box". While the chat is empty, the field hint changes every 4 s between "Talk or type a change", "Try “6 servings”" and "Try “remove item 2”" (two short examples: the desktop box is narrow and the one long example was cut). The examples line under the box is gone.
- https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#placeholder — a placeholder is a short hint; it is not the label (the field keeps its name "Type a change to the list").
