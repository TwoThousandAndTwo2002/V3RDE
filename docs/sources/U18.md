# U18 — sources for each decision

Change: U18 (branch `ui`), the web build, the web server and the service wiring.

### D1. The web build is committed

`expo export -p web` makes a static site. `npm run web:build` writes it to `mobile/web-dist`, and the change commits it, so the edge can serve it with no build step on the server. The SUP script makes it and checks that two builds give the same files.

- Expo, publish websites: https://docs.expo.dev/guides/publishing-websites/

### D2. The web server has the routes of the edge

One origin for the app and the services (no CORS). The routes, body limits, wait times, the 404 answers for the internal routes, the 410 answers for the removed routes and `index.html` for any other path come from `deploy/Caddyfile` (branch `services`, 17b4260). The earlier app's preview server (`tools/preview_web.py`) was the reference for the job of the server; this one is written new (Node standard library).

- V3RDE edge (branch services): https://github.com/TwoThousandAndTwo2002/V3RDE/blob/services/deploy/Caddyfile
- Caddy, try_files: https://caddyserver.com/docs/caddyfile/directives/try_files
- Caddy, request_body (max_size in the units of go-humanize: 1 MB = 1 000 000 bytes): https://caddyserver.com/docs/caddyfile/directives/request_body
- go-humanize, ParseBytes: https://pkg.go.dev/github.com/dustin/go-humanize#ParseBytes
- Caddy, reverse_proxy (response_header_timeout): https://caddyserver.com/docs/caddyfile/directives/reverse_proxy
- Node.js, http: https://nodejs.org/api/http.html

### D3. The cache rules

The files with a hash in the name (`/_expo/static/`, `/assets/`) are kept one year and `immutable`, only when the file is there. `index.html` and every fallback are `no-store`, so a new build is used at once.

- RFC 8246, HTTP immutable responses: https://www.rfc-editor.org/rfc/rfc8246

### D4. Safe paths and safe headers

A path with `..`, a NUL byte or a bad escape never leaves the web build. The route is chosen from the path after `.` and `..` are removed (the path the services get), without case, as at the edge. Hop-by-hop headers are not sent on; the client address headers are set to the real address.

- OWASP, path traversal: https://owasp.org/www-community/attacks/Path_Traversal
- RFC 9110, HTTP semantics (Connection, 413, 502, 504): https://www.rfc-editor.org/rfc/rfc9110

### D5. The cookie on plain http

The session cookie comes back without `Secure` and `Domain`, because the local server is plain http. Safari does not keep a `Secure` cookie on http://localhost either.

- WebKit bug 231035, Secure cookie on localhost without https: https://www2.webkit.org/show_bug.cgi?id=231035

### D6. The scan runs as a job

With one request, a scan can take longer than the write limit of the analyze service (25 s for the photo + 10 s = 35 s, `inference/cmd/inventory/main.go`), and the browser then gets no answer text. `POST /api/analyze?async=1` answers 202 with a `scan_id`; the app asks for the job about once a second (the rate the service asks for, `inference/scanjob.go`) and stops after 75 s or when the user leaves. A 200 at once (no job route) is still used.

- V3RDE scan job (branch services): https://github.com/TwoThousandAndTwo2002/V3RDE/blob/services/inference/scanjob.go
- Go, net/http Server (WriteTimeout): https://pkg.go.dev/net/http#Server
- RFC 9110, 202 Accepted: https://www.rfc-editor.org/rfc/rfc9110#name-202-accepted

### D7. Words from the error code

The code of the answer picks the words: the limit of one user (`caller_daily_cap_reached`, 429) has the same words as the limit of the service; voice `no_speech`, `busy`, `rate_limited`; a grab answer of 409 or 404 shows "This food is gone".

- V3RDE post services (branch services): https://github.com/TwoThousandAndTwo2002/V3RDE/blob/services/post/post.go
- Nielsen Norman Group, error message guidelines: https://www.nngroup.com/articles/error-message-guidelines/
