### D161. Keep a refused edit for review, never as a listing photo
- https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/ — "check if the logged-in user has access to perform the requested action on the record": the route uses the touch-up's existing owner check (one 404 for unknown and not owned).
- The edit is written to `<touch-up folder>/rejected/<touchup_id>.jpg` with a `.json` (the user, the source photo, both sha256, the mode, the model and the check's reason). Listings read item photos only from the folder itself by `photo_id`, so a refused edit can never become a listing photo. The job answer says `rejected_edit: true`; the app does not use this route.

### D162. A test waits for its touch-up jobs before it ends
- https://pkg.go.dev/testing#T.Cleanup — "Cleanup functions will be called in last added, first called order." (`go doc testing.T.Cleanup`, Go 1.24.7). A job that still runs when its test ends writes into the test's folder while the folder is removed.
- The cloud preflight of this change failed in `TestTouchupEmptyBodyWithContentType` (added in X42c): "TempDir RemoveAll cleanup: ... directory not empty", about 1 run in 7. The test now waits for each job to finish. 60 runs after the fix: no failure; `-race` 3 runs clean.
