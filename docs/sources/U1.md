# U1 — sources for each decision

Change: U1 (branch `ui`), eight app files written during the Hackathon are carried from the earlier repository (Icarus, at `457a62c`).

### D1. Carry only the files the audit gives to Hackathon work

The audit (the v3rde-audit tool, `results.jsonl` sha256 `072454ba925a3923…`) runs `git blame -M -C -C -C` on each file of the earlier repository against its pre-kickoff snapshot (tag `hackathon-start`). With `-C` given three times, blame also finds lines copied from any other file in any commit, so pre-kickoff code that was copied into a new file still counts as old. These 6 files have no old line; the 2 tests have only the 4 import lines of D2. U1 checks each carried file against the sha256 in the audit.

- Git, git-blame (`-M`, `-C`): https://git-scm.com/docs/git-blame

### D2. The 4 old import lines are written again

The audit gives `import test from "node:test";` and `import assert from "node:assert/strict";` to a pre-kickoff test file. They are written again as named imports of the same modules: `test` is a named export of `node:test`, and `strict` (the strict assertion mode) is a named export of `node:assert`. The tests make the same checks.

- Node.js, test runner: https://nodejs.org/api/test.html
- Node.js, assert, strict assertion mode: https://nodejs.org/api/assert.html#strict-assertion-mode

### D3. The tests run with Node's type stripping; the type check comes with the rebuild

`package.json` and `tsconfig.json` are written again later, so U1 runs the two test files directly with `node --experimental-strip-types --test`. Node removes the TypeScript types and runs the code. `voicerec.ts` and `webcam.ts` import from `api.ts` and `logic.ts`; `tsc` checks them when those files exist.

- Node.js, modules: TypeScript (type stripping): https://nodejs.org/api/typescript.html
- Node.js, test runner, reporters (TAP): https://nodejs.org/api/test.html#test-reporters

### D4. Branch `ui` in its own worktree; its own log file

The services work and the UI work go on at the same time from two chats. A git worktree is a second work tree of the same repository with its own branch, so branch `ui` (in `~/Documents/V3RDE-ui`) and branch `services` (in `~/Documents/V3RDE`) never share a work tree. Branch `ui` writes its log in `NEW_WORK_UI.md` and its sources in `docs/sources/U<n>.md`, so the two branches never change the same file and merge into `main` with no conflict.

- Git, git-worktree: https://git-scm.com/docs/git-worktree
- Pro Git, Basic Branching and Merging: https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging
