### D277. The address first, from one Places suggestion; then the map
- https://developers.google.com/maps/documentation/javascript/place-autocomplete-data — `AutocompleteSuggestion.fetchAutocompleteSuggestions({input, sessionToken})`, `placePrediction.toPlace()`, `place.fetchFields({fields: [...]})`; one session token from the first key to the choice (billing).
- https://developers.google.com/maps/documentation/javascript/reference/autocomplete-data — `includedRegionCodes` (here "us": the ZIP table and the directory are US only); `mainText` and `secondaryText` give the two lines of the suggestion.
- https://developers.google.com/maps/documentation/javascript/reference/place — `formattedAddress`, `location`, `addressComponents` (the `postal_code` component gives the ZIP).

### D278. The key comes from the server, never from the app files
- https://developers.google.com/maps/documentation/javascript/get-api-key — restrict a browser key by HTTP referrer and by API. The web build is in the repo (and the public repo gets it), so the key is not built in: the listings service reads it from a file on the box and gives it to a signed-in app (`GET /api/listings/config`). No key (a phone build, or no file): the X49e place row, as before.
- https://developers.google.com/maps/documentation/javascript/load-maps-js-api — the script `https://maps.googleapis.com/maps/api/js?key=...&loading=async&callback=...` (the key is the only required parameter; the weekly channel is the default).
