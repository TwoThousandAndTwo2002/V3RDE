### D299. The routes and the token, as the brief says
- https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html — "Return a consistent message for both existent and non-existent accounts"; "Ensure that responses return in a consistent amount of time"; the token must be random, long, stored securely, single use and expire. So: 202 `{}` for every valid request, and the token and the email are made after the answer (the same time with and without an account); 32 random bytes (base64url, 43 characters), only the SHA-256 in the data file, 30 minutes, one time; a new request replaces the earlier token of that user; the confirm sets the password, ends every other session of that user, and starts a new one (the same answer as login).
- https://pkg.go.dev/crypto/rand — `rand.Read` (as the session tokens).
- The link is `<RESET_LINK_BASE>/reset#token=…`: after `#`, so the browser does not send the token to a server or in a Referer header (the brief; the app reads it there, `mobile/src/signin.ts` `resetToken`).
- Limits: the address limit of signup and login, and 3 requests per email per hour (the key is the email's SHA-256). Known limit (review): three requests by another person block the reset of one address for an hour.

### D300. No sender yet: the emails go to a 0600 folder on the auth volume
- T9: no Amazon SES sender is set up yet. So `-reset-outbox /data/outbox` writes each email as one file, mode 0600, on the auth data volume (the data file next to it holds the users). An operator can open a test link there. It is a mail queue, not a log: the logs and events have the user id only (test). A file holds a live link, so each new email first removes the files older than 30 minutes (review).
- https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_SendEmail.html — the SES v2 `SendEmail` call; a sender for it is the next step when the SME sets up a verified identity and the box role. The `Mailer` interface takes it with no route change.
