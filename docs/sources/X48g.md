### D211. Muse Image is called as Meta's docs and cookbook do
- https://dev.meta.ai/docs/image-generation — `POST /v1/images/edits` takes JSON with an `images` array (1 to 10 items, each `image_url` = a URL or a base64 data URL); `tool_enablement` (`enable_image_search`, `enable_web_search`, `enable_shell`) is on by default; masks are not supported (400 `unsupported_parameter`); an edit "changes only what you ask for while keeping the rest intact".
- https://dev.meta.ai/docs/cookbook/image-editing-with-reasoning — the cookbook's edit names the change and adds "keep the items and the floor otherwise unchanged"; "Name what changes and what stays".
- https://runware.ai/docs/models/meta-muse-image/guides/editing-images — "Re-describing the whole scene reads to the model as a generation brief"; end with a preserve clause; web and image search have "nothing to look up" in an edit, so switch them off.
- So the prompts (`FixPrompt`, `BiggerPrompt`) name only the change and end with "Keep every food item, package, ... exactly as they are. Do not add or remove anything.", and the three tools are off.

### D212. Every Muse Image edit is checked in code (SSIM); a new picture is refused
- https://dev.meta.ai/resources/blog/build-with-muse-Image — the model "can rearrange the layout and redraw contents rather than reproduce your inputs exactly"; the cookbook says to compare each output with the source.
- Structural similarity: https://www.cns.nyu.edu/~lcv/pubs/makeAbs.php?loc=Wang03 (Wang, Bovik, Sheikh, Simoncelli, IEEE Trans. Image Processing 13(4), 2004, "a Structural Similarity Index"), here on the luminance at 256 px, 8 x 8 blocks. The limit is 0.5 (`SSIMMin`); the page shows every score so T9 can set it from real edits. It takes milliseconds, against 6.9 s for the Muse Spark check of today.

### D213. Studio modes in code: the real food pixels, a new background, more clarity
- https://foodshot.ai/blog/ai-food-photos-delivery-apps — delivery apps allow relighting, a colour-cast fix, "swapping a cluttered background for a clean surface", cropping and sharpening; they ban new or larger food. Studio changes only the background and the light; the food pixels come from the photo through the SAM mask.
- https://comfyui.org/en/ai-powered-e-commerce-product-enhancement-workflow — e-commerce pipelines segment the product (SAM), make a new background, relight and upscale; here the background is made in code (a light surface with a soft shadow, or the photo strongly blurred), so nothing is painted.
- https://scikit-image.org/docs/0.25.x/auto_examples/filters/plot_unsharp_mask.html — clarity is the same unsharp mask with a large radius (1/60 of the long edge, computed on a smaller copy).
- https://dev.meta.ai/docs/sam/segmenting — one concept per request: "food", "fruit", "packaged food", "product" are asked at the same time, and the first in order whose masks touch the middle of the item photo (3% to 92% of it) is used. In the service the item's title will be asked first.

### D214. A small item photo is cut again from the upload with a wider margin
- https://github.com/TwoThousandAndTwo2002/Icarus/blob/services/inference/service.go — the item photo is cut from the full upload with a 12% margin (CropMargin); for a box of about 170 px, code cannot add detail. When the item photo's long edge is under 500 px, the tool cuts the box again from the upload with a 35% margin (`WiderSource`), and the edits start from that cut; Muse Image "bigger" then has more pixels and more context, and its result is checked as in D212.
- https://runware.ai/docs/models/meta-muse-image/guides/editing-images — "Pass exactly one source image for a scoped edit"; the wider cut is still one source image.
