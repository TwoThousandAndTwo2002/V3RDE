# X52 — sources for each decision

Change: X52 (tests only), two tests that failed at times in the SUP preflight (`inference/scanjob_test.go`, `auth/auth_test.go`; NEW_WORK.md 98).

Own evidence: a SUP preflight run failed once in `TestAnalyzeAsyncSamePhoto` (`inference/scanjob_test.go:110`) with "TempDir RemoveAll cleanup: unlinkat .../003: directory not empty". The test starts the jobs `other` (user u2), `code` (a barcode read) and `again` (service `f`, after a failure) and returns without waiting for them; their goroutines write the scan files into the test's temporary folder while the testing package removes it. A run of the old and the new test, 4 times 30 runs each with all CPUs busy (two busy loops a CPU): the old test failed 2 of 4 times with this error, the new test 0 of 4.

### D334. Wait for every started job before the test returns
- https://pkg.go.dev/testing#T.TempDir — "The directory is automatically removed when the test and all its subtests complete"; a write after the test ends races that removal. The test now polls each job (the `poll` helper the test already has) until it is no longer running.

### D335. A deadline in place of a try count
- https://pkg.go.dev/time#Time.Before — the `poll` helper waited 500 × 5 ms (2.5 s). Under a full SUP test run (all modules at once) a job can take longer, and the helper then failed with "the scan job did not end". It now polls until a 30-second deadline; a fast job still ends the poll at once.

### D336. The login time test takes the fastest of 7 tries
- https://pkg.go.dev/builtin#min — `TestLoginMissTakesTheHashTime` (auth) failed once in the X51 preflight ("FAIL: TestLoginMissTakesTheHashTime (2.28s)"; X51 changes no auth file). It compared the middle of 3 timed logins of one kind with the middle of 3 of the other kind, taken one kind after the other, so a busy moment during one kind failed it. It now takes the fastest of 7 tries of each kind, in turn. A login with no hash stays fast in every try: with the decoy hash taken out of `store.go` the test fails (a mutation run); with all CPUs busy it passed 10 of 10 runs.

Review (independent, 15 minutes at most): OK, no defect. The job's file writes all end before the job is marked done, so a poll that sees the end means no more writes; no other test in the package leaves a job or a writer running. One hardening point, done: each wait checks its answer is 200 (a 404 would end the wait at once and hide the old failure). The auth test change (D336) came after the review.
